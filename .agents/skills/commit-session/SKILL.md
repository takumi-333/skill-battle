# セッション完了時のコミット

特定のissueについて実装と検証が完了したときに、そのissueに関係する変更だけをコミットする。コミット前に変更範囲とissueの状態を確認し、解決済みのissueが未アーカイブならアーカイブしてからコミットする。

## 手順

1. 対象issueを特定する。
   - issue番号またはファイル名を確認する。
   - 対象issueの実装と検証が完了していることを確認する。
   - 未解決の課題や未完了のタスクが残っている場合は、コミットせずに状況を報告する。

2. 変更範囲を確認する。
   - `git status` と `git diff` で作業ツリーを確認する。
   - 対象issueに関係するファイルだけをコミット対象にする。
   - 他の作業による無関係な変更は、取り消したり上書きしたりしない。
   - 同じファイルに無関係な変更が混在している場合は、該当部分だけを選択してステージする。安全に分離できない場合はコミットを止めて報告する。

3. 解決済みissueをアーカイブする。
   - 対象issueが解決済みで、`docs/issues/archives/`に同名ファイルがない場合は、元の内容を変更せずに移動する。
   - 通常は `docs/issues/issue-*.md` から `docs/issues/archives/issue-*.md` へ移動する。
   - まだ解決していないissueはアーカイブしない。
   - アーカイブ先に同名ファイルがある場合は、上書きせずに停止して報告する。

4. 対象変更だけをステージする。
   - 実装変更、必要なドキュメント変更、issueのアーカイブ移動だけを対象にする。
   - ステージ後に `git diff --cached` を確認し、意図しないファイルや変更が含まれていないことを確認する。

5. コミットする。
   - コミットメッセージには、対象issueが分かる情報と変更内容を簡潔に含める。
   - コミット前に、対象外の変更を誤って含めていないことを再確認する。
   - 変更がない場合や対象範囲を確定できない場合は、空コミットや推測でのコミットを行わない。

6. コミット後に確認する。
   - `git status` でコミット結果と残った変更を確認する。
   - コミットハッシュ、コミット対象、残った未コミット変更があればその内容を報告する。
