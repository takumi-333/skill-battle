# UIレイアウト編集方針

## 目的

固定UIの配置とサイズをGodotエディタから直接調整できる状態を保ち、実行時コードによるレイアウト上書きを最小限にする。

## 基本原則

- 位置、サイズ、アンカー、階層、固定文言など、ゲーム状態に依存しない見た目は `.tscn` に保存する。
- 対戦人数によって固定配置が異なる画面は、人数ごとのレイアウトルートをシーン内に用意する。
- 2人用と3人用のロビー、および2人用と3人用のHUDは、それぞれ独立したレイアウトとしてGodotエディタから編集できるようにする。
- エディタ上で配置を確認できるよう、名前、HP、Ready状態などには仮の表示値を設定する。
- 実行時に切り替えてよいのは、使用するレイアウトルートの表示状態と、ゲーム状態に由来する動的な表示内容・操作状態だけとする。

## 実行時に更新してよい内容

- プレイヤー名、キャラクター名、HP、残り時間、クールダウン
- Ready、接続、観戦などの状態表示
- キャラクター画像、スキルアイコンなど選択結果に応じる素材
- 対戦モードに対応するレイアウトルートの表示・非表示
- ローカルプレイヤーだけが操作できるボタンの表示・無効状態

## 実行時に上書きしない内容

- 固定UIノードの座標とサイズ
- 固定UIノードのアンカーと階層
- 人数別レイアウト内のプレイヤーカード間隔
- HUD内のHPバー、名前、状態表示の配置

実行時に固定配置の変更が必要になった場合は、まず人数別または状態別のシーンレイアウトとして表現できないか検討する。コードによる配置変更が不可避な場合だけ、理由と対象を設計文書へ記録する。
