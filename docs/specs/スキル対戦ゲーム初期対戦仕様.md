# スキル対戦ゲーム 初期対戦仕様

## 1. 目的

プレイヤーの得意操作を技の発動に使う、オンライン1対1対戦ゲームの初期版を定義する。

初期版で検証するのは、**課題を解いて強い技を出す気持ちよさ**と、**集中中の相手の攻撃を避けながら課題を完遂する駆け引き**である。

## 2. 対象範囲

### 実装対象

- オンライン1対1のルーム対戦
- 1つの見下ろし視点マップ
- 150秒の1ラウンド制
- 打鍵士、算術士、詠唱者の3キャラクター
- 移動、通常攻撃、固有課題による小技・大技
- 集中状態、集中エフェクト
- 勝敗・課題成績を表示するリザルト

### 今回は対象外

- 多対多対戦、観戦、ランクマッチ、マッチメイキング
- 育成、レベル、スキルポイント、スキルリセット
- 複数マップ、追加キャラクター、コスメティック要素
- 完全な不正検知、再接続

対象外の機能は、初期対戦が面白いと確認できた後に別仕様として追加する。

## 3. 試合の流れ

1. プレイヤーはルームを作成、またはルームに参加する。
2. 両者が打鍵士・算術士・詠唱者からキャラクターを選ぶ。
3. 両者の選択完了後、両者を対戦画面へ遷移させて `READY` を表示する。この間は操作を受け付けない。
4. `FIGHT` を表示すると同時に試合を開始する。制限時間は設定値（初期値は150秒）とし、この時点から計時する。
5. どちらかのHPが0になった時点で勝敗を確定し、対戦ロジックを停止する。対戦画面は2秒間の決着演出を表示し、この間の表示用アニメーションは0.20倍速で進行する。
6. 決着演出後、リザルト画面に勝敗と課題成績を表示する。
7. 時間切れの場合、残HPが多いプレイヤーを勝者とする。同HPなら引き分けとし、決着演出を挟まずリザルト画面へ遷移する。

## 4. 共通対戦ルール

### 操作

全キャラクターは、次の共通操作を持つ。

| 操作 | 内容 |
| --- | --- |
| 移動 | 見下ろし視点のフィールドを上下左右に移動する。入力方式はキーボードを基本とする。ジャンプは持たない。 |
| 通常攻撃 | 専用の攻撃ボタンで、課題なしに低威力の攻撃を行う。集中状態では使用できない。 |
| 固有スキル開始 | 小技または大技を選び、対応する課題UIを開始する。 |
| 課題の中止 | 集中状態を任意に終了する。技は発動せず、短い再使用待ち時間を受ける。 |

回避アクションは初期版に実装しない。

### マップとカメラ

- マップは2Dの見下ろし視点とする。プレイヤー、弾、設置技、集中エフェクトを同一画面で見渡せる構図にする。
- 初期マップのワールドサイズは 1680×774 px とし、P1 は `(200, 260)`、P2 は `(1480, 260)` から開始する。
- カメラは試合中、各クライアントの操作プレイヤーを画面中央に捉える。ローカル対戦では現在の操作対象を中央に捉える。
- 初期マップには、プレイヤーの進行を遮る複雑な地形を置かない。まずは移動、弾、設置技、集中状態の読みやすさを検証する。

### HPとダメージ

- 各プレイヤーは最大HPを持つ。
- 攻撃が命中すると、技ごとに定義されたダメージを受ける。
- 同じフレームに複数の攻撃が命中した場合、すべてのダメージを適用する。
- HPが0以下になったプレイヤーは敗北とする。

### 技の基本ルール

- 各キャラクターは通常攻撃、小技、大技を1つずつ持つ。
- 通常攻撃中は、攻撃開始時の位置と向きを完了まで固定する。
- 小技は短時間・低難度の課題で発動でき、低い成績でも最低限の効果を持つ。
- 大技は長時間・高難度の課題で発動でき、合格点未満では発動しない。
- 小技・大技には個別のクールダウンを設定する。
- 課題を中止または失敗した場合、対象のスキルに短い失敗クールダウンを設定する。

具体的なダメージ、クールダウン、課題の制限時間、合格点は `SkillDefinition` の調整値として保持し、本仕様では固定しない。

## 5. 集中状態と課題

### 集中状態への移行

プレイヤーが小技または大技を開始すると、そのキャラクターは即座に集中状態へ移行する。

- 集中状態であることを、キャラクター上のエフェクトで両プレイヤーに表示する。
- 集中状態では移動速度を通常時より大幅に下げる。
- 集中状態では通常攻撃を使用できない。
- 集中状態では別の課題を開始できない。
- 相手が集中状態でも、自分が集中状態でなければ課題を開始できる。両プレイヤーの課題は独立して進行する。
- 課題の成功、任意中止、時間切れ、または誤答による失敗で集中状態を終了する。
- 集中中にダメージを受けても、課題およびスキル発動は中断されない。
- 集中エフェクトは、画面内で課題中のプレイヤーを即座に判別できることを優先する。

## 6. キャラクター仕様

### 打鍵士

| 項目 | 仕様 |
| --- | --- |
| 課題 | 画面に表示された単語または短文を入力する。 |
| 小技 | 短い単語を正しく入力すると、前方へ弾を放つ。成績により弾速またはダメージを補正する。 |
| 大技 | 長文を合格点以上で入力すると、前方へ貫通弾を放つ。成績によりダメージを補正する。 |
| 入力判定 | 目標文字列との一致、誤入力数、課題開始から完了までの時間を採点に使用する。 |

### 算術士

| 項目 | 仕様 |
| --- | --- |
| 課題 | 四則演算の問題に数値で回答する。 |
| 小技 | 正解すると、自身を短時間強化する。効果内容はスキルごとに固定する。 |
| 大技 | 難しい問題に合格点以上で正解すると、相手の行動範囲を制限する設置技を発動する。 |
| 入力判定 | 回答の正誤と、課題開始から回答までの時間を採点に使用する。 |

### 詠唱者

| 項目 | 仕様 |
| --- | --- |
| 課題 | 目標図形をポインターでなぞる。 |
| 小技 | 短い線をなぞると、近距離の範囲攻撃を行う。 |
| 大技 | 円または星を合格点以上でなぞると、持続する魔法陣を設置する。 |
| 入力判定 | 記録した軌跡を目標図形と正規化して比較し、形状の一致度と完了時間を採点に使用する。 |

課題の具体的な問題文・図形・難度は、データとして追加・差し替え可能にする。

## 7. 課題と採点

### 共通フロー

```text
スキル選択
  → 集中状態開始
  → 課題UI表示・入力受付
  → 成功 / 任意中止 / 失敗
  → 成功時のみ採点
  → 技の性能を決定して発動
```

### スコア

- 成功した課題は、0〜100点のスコアを持つ。
- スコアは正確性と入力時間をもとに算出する。
- 技はスコアから補正値を得る。補正対象はスキルごとにダメージ、弾速、持続時間、効果量のいずれかとする。
- 大技はスキルごとに定めた合格点以上の場合のみ発動する。
- 中止・時間切れ・誤答で終了した課題にはスコアを付与しない。

課題UIは、プレイヤーの操作対象と進捗を明瞭に表示しつつ、対戦フィールドと相手の集中状態が見える領域を残す。

## 8. UI仕様

### 対戦HUD

- 両プレイヤーのキャラクター名、HPバー、通常攻撃・小技・大技の再使用待ち時間を表示する。
- 集中状態のプレイヤーには集中エフェクトを表示する。
- 画面中央に残り時間を表示する。
- 自分の固有課題は `ChallengeLayer` に表示する。

### リザルト

- 勝敗または引き分けを表示する。
- 両プレイヤーの残HPを表示する。
- 自分の課題ごとの成功回数、平均スコア、最高スコアを表示する。
- 「もう一度対戦」と「ロビーへ戻る」を選択できる。

## 9. オンライン対戦仕様

### 接続方式

2026-09-05 以降のオンライン対戦は、プレイヤーホストではなく専用対戦サーバーを権威とする。公開ルームの作成・一覧・参加予約は Lobby API が行い、予約済みプレイヤーだけが短命トークンで Dedicated Server へ ENet 接続する。ローカル練習・デバッグ対戦はこの経路を使わない。

- Godot の高レベルマルチプレイヤーAPIと `ENetMultiplayerPeer` を用いる。
- ルーム作成者を含む両プレイヤーは、Lobby APIから取得した接続先と短命参加トークンを使ってDedicated Serverへ接続する。
- Dedicated Serverが試合の権威を持ち、両クライアントから入力を受けて試合状態・採点・勝敗を判定し、状態を両者へ同期する。
- ルーム作成・公開一覧・参加予約・接続情報の発行はLobby APIが行う。自動マッチングは初期版の対象外とする。

### 権威を持つ判定

Dedicated Serverは以下を判定し、結果を同期する。

- キャラクターの位置、HP、攻撃命中、クールダウン、試合時間
- 集中状態の開始・終了、課題の進行・成否
- 課題の内容、開始時刻、採点、技の発動可否
- 勝敗

クライアントは操作入力と課題への入力内容をDedicated Serverへ送信する。クライアントが算出したスコアや発動結果を正として扱わない。

### 同期要件

- キャラクター位置と攻撃の状態を両プレイヤーに同期する。
- 集中エフェクト、課題の成功・失敗は両プレイヤーで同じ結果になる。
- 通信遅延により見た目の補間が発生しても、ダメージ・課題の成否・勝敗の最終判定はホストの結果を採用する。

## 10. データ構成

| データ | 主な内容 |
| --- | --- |
| `CharacterDefinition` | キャラクターID、表示名、見た目、通常攻撃、スキルID |
| `SkillDefinition` | スキルID、課題種別、難度、クールダウン、スコア補正、攻撃効果 |
| `ChallengeDefinition` | 問題文・正答・目標図形・制限時間などの課題データ |
| `MatchConfig` | 制限時間、最大HP、マップID、試合ルール |
| `MatchState` | 試合時間、プレイヤー状態、HP、集中状態、クールダウン、勝敗 |

データ定義は Godot の `Resource` を基本とし、キャラクター・スキル・課題の追加をコード変更なし、または最小限の変更で行える形にする。

## 11. 受け入れ条件

以下を満たしたとき、初期対戦仕様は実装完了とみなす。

- 2人がネットワーク経由で1つのルームに入り、同じ試合を開始できる。
- 3キャラクターそれぞれで通常攻撃・小技・大技を使用できる。
- 課題開始時に集中エフェクトが両プレイヤーに表示される。
- 集中中に受けたダメージでは課題が中断されず、課題を完遂すればスキルを発動できる。
- 課題の成功時だけスコアに応じた技が発動する。
- HP0または時間切れで勝敗が確定し、両プレイヤーに同じ結果が表示される。
- リザルトで勝敗と自分の課題成績を確認できる。

## 12. 調整して決める項目

- 集中中の移動速度、失敗クールダウン
- 各課題の制限時間、難度、採点式、スコアによる補正量

これらは初期値を設定して実装し、プレイテストで対戦コアを確認しながら調整する。
## 対戦形式

Dedicated Server のルームは `match_mode` を持つ。省略時は `duel` とする。

| mode | 定員 | HP 0 時 | 時間切れ |
| --- | --- | --- | --- |
| `duel` | 2 | 相手の勝利として終了 | 残り HP の高い側、同値は引き分け |
| `free_for_all` | 3 | 当該プレイヤーを敗北・操作不能にし、残りが 1 人になるまで継続 | 生存者の残り HP が最も高い側、同値は引き分け |

FFA では死亡済みプレイヤーは移動、通常攻撃、スキル、被弾の対象外となる。最終の生存者には `placement = 1` を、敗北者には敗北時点の順位を記録する。同 tick で最後の生存者が確定しない全滅は引き分けとする。

FFA の通常攻撃は、発動者の照準方向・射程・角度内にいる生存中の敵全員に命中する。範囲攻撃、設置技、貫通弾も判定範囲内の生存中の敵全員に適用する。追尾弾だけは最も近い生存敵を1人追跡し、対象の脱落時は別の最も近い生存敵へ再取得する。

FFA で脱落したプレイヤーは観戦専用状態になる。移動、通常攻撃、スキル、課題入力は受け付けず、カメラは最後に撃破したプレイヤーを追従する。追従対象が脱落・切断した場合は、残る生存者へ切り替える。観戦者への snapshot には他プレイヤーの課題の正解・入力内容・なぞり軌跡を含めない。
