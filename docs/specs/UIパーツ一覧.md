## 目的と適用範囲

本書は、プロジェクトで使用するUIアセットの管理名簿である。
UI刷新計画に限らず、新規画面・機能追加を含むすべてのUIアセットを、本書で一意に管理する。

各アセットについて、管理名、用途、形式・サイズなどの規格、状態、使用画面、実ファイルの配置先、制作状況を記録する。新規アセットを作成・取得した場合は、本書に追加する。

## 責任分離

本書はUIアセットの識別、UIに固有の設計方針、実装上の規格を扱う。世界観、配色、質感、文字表現などのアートディレクションは定義しない。これらは[世界観・アートディレクション](世界観・アートディレクション.md)を正とする。

画面ごとの構成・導線や、UI刷新の進め方は[UI刷新計画](../ideas/UI刷新計画.md)を参照する。

## UIデザイン方針

## メニュー配置の編集

オンライン対戦画面のレイアウトは、[`res://resources/menu_layout.tres`](../../resources/menu_layout.tres) に分離して管理する。

Godotで `scenes/main.tscn` を開き、ルートの `MatchPrototype` ノードを選択して、インスペクターの `Menu Layout` をクリックすると、画面を構成する各要素の `position` と `size` を編集できる。変更後にF6またはF5で実行すれば、その値を反映した画面を確認できる。

画面の生成・ボタンの挙動・素材の選択は `scripts/match_prototype.gd` に残す。したがって、AIやコードレビューでは `.tres` の数値差分とGDScriptをそれぞれ追跡でき、ビジュアル調整と実装ロジックを混在させない。

### 情報の優先順位

- 1画面で最初に見せる操作は1つに絞り、主ボタンとして他の操作より大きく扱う。
- 補助操作、戻る操作、破壊的な操作は、主ボタンと見分けられる大きさ・位置・状態にする。
- 対戦中は、対戦フィールド、相手の状態、残り時間、HP、現在操作する課題の順に優先して表示する。課題UIはフィールドを必要以上に覆わない。
- 接続、準備完了、クールダウン、入力エラーなど、プレイヤーが次に取る行動を左右する状態は、対応する操作の近くに表示する。

### 操作と状態のフィードバック

- 操作可能な部品は、少なくとも通常、ホバー／フォーカス、押下、無効の状態を持つ。
- 選択・準備完了・接続済みなどの確定状態は、通常状態と明確に区別する。色だけではなく、枠、チェック、ラベル、形状変化のいずれかを併用する。
- 無効状態では、操作できない理由をツールチップまたは近接する補足テキストで確認できるようにする。
- 成功、情報、警告、エラーの通知は、アイコンと短い文章を併記し、色だけで意味を伝えない。
- クリック・決定・接続開始・準備完了などの操作には、短い視覚または音の反応を返す。

### レイアウトと再利用性

- 同種のアセットは、画面が変わっても同じ役割・同じ状態表現・同じ操作順序で使用する。
- 戻る・閉じるなどの共通操作は、各画面で位置を統一する。
- パネル、ボタン、一覧行、ダイアログは、内容量に応じて伸縮できる構造にする。枠素材は原則9-slice対応とする。
- 文字量が増減するラベルや通知は、固定幅での切り捨てを避け、最小幅・最大幅・折り返し規則を実装時に定める。
- アイコンだけで操作を示す場合は、ツールチップまたはアクセシブルなラベルを用意する。

### 可読性とアクセシビリティ

- 本文、数値、入力値は背景との十分なコントラストを確保し、装飾・ノイズ・発光を重ねない。
- 残り時間、HP、入力中の課題、接続エラーは、遠目でも認識できる文字サイズと余白を確保する。
- 状態やチーム・プレイヤーの区別を、色だけに依存しない。名前、アイコン、位置、枠などを組み合わせる。
- キーボード操作時も、現在フォーカスしている部品が明確に見えるようにする。

## 管理ルール

- 管理名は `ui_<分類>_<用途>` の小文字スネークケースとする。例：`ui_button_primary`、`ui_icon_back`。
- 各アセットは、この台帳内で重複しない管理名を持つ。
- 実ファイルを追加した場合は、アセットの配置先を `res://` 形式で記録する。未作成の場合は `未作成` と記載する。
- サイズが可変のアセットは、基準サイズまたは使用可能な最小・最大サイズを記録する。
- ボタンやカードなど状態を持つアセットは、必要な状態を記録する。
- 同一アセットを複数画面で使用する場合は、使用画面をすべて記録する。
- 仕様変更・置換・廃止時も、先に本書を更新してから実ファイルと実装を変更する。
