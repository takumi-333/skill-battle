# 設計書

## 調査方針

通常攻撃の描画経路から赤枠を生成するデバッグフラグと、その設定箇所を特定する。`draw_player()` が `draw_debug_normal_attack_hit_area()` を無条件に呼んでいるため、画面がデバッグ対戦 (`screen == "debug_waiting"`) の場合だけ呼び出す。

オンラインルームについては、専用サーバーの参加・切断・予約解放の状態遷移と、ルーム一覧の人数算出を追跡する。`MatchSession.leave()` は専用サーバー内の枠を解放済みだが、ロビーAPIの SQLite 予約は更新されない。切断通知にスロット番号を含め、ロビーAPIが当該予約を即座に解放する。

## 検証方針

- 攻撃のデバッグ表示条件をスクリプトテストまたは描画設定の単体テストで確認する。
- 参加、退出、再参加の順にルームスロットが解放されることをネットワークシミュレーションテストで確認する。
- Godotのヘッドレス起動・既存テストを実行し、パースエラーと回帰を確認する。
