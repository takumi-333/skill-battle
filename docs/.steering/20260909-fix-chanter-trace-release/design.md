# 設計書

## 方針

マウスボタン処理を押下と解放で分ける。押下時だけキャンバス内判定を行い、解放時は課題が有効であればポインタ位置にかかわらず既存の送信または採点処理を実行する。

## データフロー

1. キャンバス内のマウスダウンで点列を初期化し、開始点を追加する。
2. 押下中のキャンバス内マウス移動で点列を追加する。
3. マウスアップ時はキャンバス外でも既存の `challenge_trace` 送信または `evaluate_trace_result()` を実行する。
4. 成功または失敗処理が `end_active_challenge()` を通じて点列を消去する。

## テスト方針

- 入力処理を静的・ヘッドレスで検証し、構文エラーがないことを確認する。
- 可能なら Godot の既存テストを実行する。
