# リアルタイム対戦試作 — 設計

## 方針

現状の `MatchPrototype` を試作の入口にする。入力と対戦状態はローカルで処理するが、P1/P2の入力を分離し、将来はP2入力をネットワーク入力に置き換えられる形を保つ。

## 通常攻撃

- 攻撃開始時に攻撃者の向きから短い近接範囲を生成する。
- 相手が範囲内なら1回だけダメージを与える。
- 攻撃中は短い再使用待ち時間を設ける。
- 斬撃の向きと届く範囲を画面に表示し、手触りを確認できるようにする。

## 表現

- マップ: 草地・土・石のタイル風の配色と、外周の壁をコードで描画する。
- キャラクター: 頭・胴体・武器を持つ小さな2Dシルエットとして描画する。
- 実アセットへ置き換えるまで、コード描画で視認性とサイズ感を検証する。

## 全体実装ロードマップ

### 打鍵者の小技

- P1 は `Q` で「ブレード（`blade`）」のタイピング課題を開始する。課題UIは画面左下に置き、マップを見続けられるようにする。
- `LineEdit` の送信で正誤を判定する。成功時は経過時間から60〜100点を算出し、得点に応じてダメージを補正した弾を前方へ発射する。
- 集中中は移動速度を35%にし、通常攻撃と別課題の開始を拒否する。キャラクター周囲の光と「集中中」表示で両者が認識できるようにする。
- `Esc`、制限時間切れ、誤入力で集中を終了し、技を発動しない。被ダメージによる中断ゲージは次の実装フェーズに追加する。

## フェーズ2〜5実装メモ（ローカル試作）

- `MatchPrototype` は `MatchController` を継承し、試合状態（`MatchState`）、課題UI（`ChallengeLayer`）、Resourceデータ定義を分離した。
- ロビーで3キャラクターを選択し、両者の準備完了から3秒カウントダウン後に同じマップへ遷移する。
- 打鍵者は短文／長文タイピング、算術士はランダム加算／乗算、詠唱者はマウス軌跡の線／星課題を使う。成功スコアは小技・大技の効果とリザルトへ渡す。
- 小技は打鍵者の弾、算術士の自己強化、詠唱者の近距離衝撃波。大技は貫通弾または範囲に残る魔法陣とする。
- キャラクターSVGを `assets/characters/` に追加し、コード描画の仮形状から置き換えた。
- ENet接続、招待コード解決、ホスト権威同期はフェーズ6で実装する。

## フェーズ6実装メモ（ENet 1対1）

- Godotの`ENetMultiplayerPeer`で、ホストはUDPポート`7000`に最大1参加者のルームを作成する。参加者は接続画面で`IP:ポート`を入力する。
- 初期版の招待コードは外部サービスを使わず、接続先文字列（例: `192.168.1.20:7000`）を共有する方式とする。インターネット越しではホスト側のUDP 7000許可または将来の中継サービスが必要になる。
- ホストを唯一の権威とし、クライアントはP2の移動・攻撃・スキル開始・課題回答／なぞり軌跡だけをRPCで送信する。HP、命中、集中、中断、クールダウン、採点、勝敗はホストだけが更新する。
- ホストは約20Hzでスナップショットを送信する。クライアントはプレイヤー座標を補間して描画する。

## 次の段階

1. 対戦状態とResourceデータを整備し、集中中断を全キャラクター共通の仕組みにする。
2. 打鍵者の大技、算術士の計算課題、詠唱者のなぞり課題を、共通の採点・集中フローへ載せる。
3. 選択、カウントダウン、HUD、リザルト、シーン分割を完成させる。
4. ENetホスト権威にローカル入力を置き換え、ルーム接続から結果同期までを実装する。
5. 仕様の受け入れ条件に沿って、2クライアントで対戦を検証・調整する。
