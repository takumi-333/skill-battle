# 設計書

## UI

ロビーシーンの既存カードを維持し、左右ボタンのフレームを各ボタンの背面へ合わせる。選択ボタンは自分のカード側だけを `refresh_lobby_label()` で表示する。準備完了ボタンは共通の1ノードを画面下中央へ配置し、ローカルプレイヤーIDに応じて `p1_ready` または `p2_ready` を切り替える。

相手プレビューにはキャラクター固有の立ち絵を設定せず、接続済みなら `shadow_idle.png` を設定する。相手情報ラベルは「対戦相手」のみとし、キャラクター名を含めない。

ホスト専用の開始ボタンを右下に追加し、`p1_ready && p2_ready` を `disabled` 条件にする。

## ネットワーク

クライアントの準備操作は既存の `receive_remote_lobby_choice(selection, ready)` RPC でホストへ送信する。ホストは状態同期で準備状態を配信する。両者準備完了時の自動遷移は廃止し、ホストの開始ボタンから countdown を開始する。これにより準備完了とゲーム開始の責務を分離する。

## 検証

- `godot --headless --path . --editor --quit` でシーン・スクリプトの読み込みを確認する。
- `godot --headless --path . --quit-after 2` で実行時エラーを確認する。
