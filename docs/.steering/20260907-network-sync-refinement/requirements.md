# 要求内容

## 概要

Dedicated Server を使うオンライン対戦について、サーバー権威を維持したまま操作感と状態同期の効率を改善する。対象は、固定60Hzシミュレーション、状態snapshotの送信方式、入力確認番号、クライアント補間、snapshotの軽量化である。

## 実装対象

1. Dedicated Server の試合シミュレーションを固定60Hz tick で実行する。
2. 継続的な状態snapshotを `unreliable_ordered` で送信し、古い状態の再送待ちを避ける。入室・Ready・発動イベント・結果操作は reliable のままにする。
3. snapshotにサーバーtickとslotごとの最終受理入力連番を含める。
4. Dedicated Clientでは連続状態を即時置換せず、受信状態を短時間補間して描画する。ローカルプレイヤーの状態はサーバー権威のsnapshotを正とする（今回、入力再生による完全な予測は実装しない）。
5. snapshotの送信対象・フィールドを必要な表示状態へ限定し、各クライアントに不要な他者の課題詳細を送らない。スキル実体は活動中のものだけを送る。

## 受け入れ条件

- [ ] シミュレーションはフレームレートではなく、1/60秒の固定tick単位で進む。
- [ ] 大きなフレーム遅延で無制限にcatch-upせず、遅延分を安全に切り詰める。
- [ ] root RPCのsnapshot送受信契約が双方で `unreliable_ordered` 一致となる。
- [ ] snapshotに `server_tick` と `input_acknowledgements` が含まれる。
- [ ] クライアントはDedicated Serverから届く連続状態を補間して表示し、フェーズ・結果・Ready・課題などの離散状態は直ちに反映する。
- [ ] snapshotは受信者本人の進行中課題だけを含み、`answer` を含まない。
- [ ] 既存のサーバー権威シミュレーション、ロビー、リザルトの挙動を壊さない。
- [ ] 自動テストとGodotヘッドレス起動でGDScriptのパースを確認する。

## スコープ外

- 入力履歴の再生を伴う完全なクライアント予測・サーバー補正。
- 近接攻撃のラグ補償（過去位置巻き戻し）。
- snapshot差分同期・圧縮・クライアントごとのベースライン確認応答。
- なぞり課題の不正対策。
