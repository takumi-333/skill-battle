# 要件

## 目的

既存の Dedicated Server 方式を維持したまま、1 対 1 の `duel` と 3 人 FFA の `free_for_all` をモードとして扱えるようにする。今回の実装対象は FFA の最小垂直スライスであり、既存の duel の動作と外部 API の既存呼び出しを維持する。

## 機能要件

- `MatchProtocol` に `duel` / `free_for_all` とモード別定員を定義し、既定は duel とする。
- `MatchSession` はモードの定員に応じて slot、Ready、入力、再試合、snapshot を構成する。
- `MatchSimulation` は有効 slot、死亡状態、順位、FFA の勝敗・時間切れ判定を扱う。
- FFA では死亡した参加者を行動・被弾対象から除外し、残存者が 1 人になった時点で終了する。同 tick の全滅は引き分けとする。
- 攻撃対象の選択は生存中の敵に限定する。既存の duel の挙動を変えない。
- Lobby API と SQLite は作成時にモードを記録し、予約可能な slot と定員をモードから決める。既存 API の省略時は duel。
- クライアントはモードを指定して部屋を作成し、一覧とロビーでモード・定員を表示する。
- 仕様書に duel と free_for_all の差異を追記する。

## 受け入れ条件

- 既存の 1 対 1 テストが成功する。
- 3 人 FFA の全員入室・Ready・開始、1 人の敗北後の継続、最後の 1 人の勝利、同時全滅の引き分け、時間切れの HP 比較をテストする。
- Lobby API テストで `free_for_all` の部屋が 3 slot を予約でき、duel が引き続き 2 slot であることを確認する。
- Godot の headless 起動でスクリプトエラーがない。

## スコープ外

- 3 人 HUD/リザルトを全面的にデザインし直すこと。
- 観戦カメラの切替 UI と運用サーバーへの実機 3 クライアント接続。
