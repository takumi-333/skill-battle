# 設計書

## 調査結果と原因

1. ルーム一覧は `Connection/RoomList` と `RefreshButton` として接続画面下部に常時置かれ、`JoinButton` は選択済みの `ItemList` を読むだけである。そのため、要求されたモーダル表示・各行の入室操作が実装されていない。
2. `refresh_lobby_label()` は `multiplayer.has_multiplayer_peer()` をクライアント接続の判定に使う。この値はルームへ最初の一人が接続した時点で真になるため、専用サーバーへ接続済みだが相手不在の状態でも影を表示してしまう。
3. `lobby_screen.tscn` の選択ボタン枠はボタンと異なる Y 座標にあり、`z_index = -1` によって親パネルより後ろへ描画される。ホームボタンは対応するフレームを持たない。
4. `create_lobby_ui()` は `StartButton` 用のテクスチャを実行時に追加しており、シーンにある枠と二重管理になっている。これは固定UIをシーンで編集する方針に反する。

## UI構成

- `connection_screen.tscn` に常時表示の `RoomList` と `RefreshButton` を置かず、`RoomListModal` を追加する。
- モーダルは全画面ディマー、`panel_frame.png` のフレーム、一覧行のコンテナ、更新・閉じるボタンで構成する。
- 可変個数のルーム行だけをスクリプトで生成し、各行の入室ボタンはその行の room ID をキャプチャして既存の予約取得処理を呼ぶ。
- `lobby_screen.tscn` で全ボタンフレームをボタンと同じ矩形に置き、親パネルより前・ボタンより後ろに描画する。ホーム用フレームを追加する。

## 状態判定

- 専用サーバーのスナップショットへ `connected_slots` を含め、ローカルプレイヤー以外のスロットが在席しているかを判定する。
- 従来のプレイヤー直結ホストでは、接続ピア数を相手接続判定に使う。
- ローカル側のプレビューは常に表示し、相手側のプレビュー・状態アイコンは相手接続時だけ表示する。

## 検証

- ルーム一覧受信・モーダル表示・行の参加処理を単体テストで確認する。
- ロビーの相手プレビュー可視性を、相手不在・在席のスナップショットで確認する。
- `godot --headless --path . --editor --quit` とテストシーンの実行でパース・ノード参照エラーを確認する。
