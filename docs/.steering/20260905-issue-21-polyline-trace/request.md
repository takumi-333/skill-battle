# 詠唱士の紋章なぞり採点を双方向Polyline方式へ変更

## 背景

現在の詠唱士のなぞり採点は、入力点と目標Polylineの距離平均、および目標点のカバー率を線形に加重している。入力点の密度、描画方向、始点・終点、余計な往復などの影響を十分に扱えていない。

詠唱士のなぞり課題を、最終的な軌跡形状を評価する双方向Polyline方式へ変更する。

## 対象

- `scripts/match_prototype.gd` の詠唱士なぞり入力・採点処理
- なぞり軌跡を描画するUIコンポーネントの表示処理
- ゲーム本体とは分離した、なぞり採点ロジック検証ツール
- 必要に応じて詠唱士の採点仕様書、関連するテストまたは検証用コード

## なぞり線の表示仕様

なぞり中に表示するユーザー軌跡は、目標紋章の見た目と区別しつつ、紋章をなぞっている感覚が伝わる表示にする。

1. 線の内側は、インナーグローに使用している線の色を使う。
2. 線の外側は、詠唱士のメインカラーである紫を使う。
3. なぞり線の基本太さは、表示中の目標紋章の線の太さと同じにする。

内側・外側の二重描画を行う場合も、採点に使用する軌跡座標には影響させない。色や装飾は表示専用とし、入力軌跡の幾何学的評価は従来のPolylineデータを使用する。

## 採点ロジック検証ツール

ゲーム本体の対戦フローとは別に、採点ロジックの妥当性を確認するためのスタンドアロン検証ツールを作成する。

### 必須機能

- 実際に評価対象となる円・星などの紋章を画面に表示する。
- マウスまたはペン入力で表示中の紋章をなぞれるようにする。
- MouseUp時に、ゲーム本体と同じ前処理・距離計算・NG判定・スコア計算を実行する。
- 採点結果を即座に表示する。
- 少なくとも以下の結果を確認できるようにする。
  - 最終スコア
  - NG判定の有無と理由
  - MeanError、P90Error、P95Error、P99Error
  - CoverageError
  - TargetLength、UserLength、LengthRatio、LengthPenalty
  - 正規化後のError
- 目標紋章、入力軌跡、カバーできていない区間、目標から外れた入力区間を視覚的に確認できるようにする。
- 紋章の種類、紋章サイズ、入力許容距離、連続Gap閾値、スコア係数などを変更して結果を比較できるようにする。
- 始点・終点、時計回り・反時計回り、入力速度、入力点の密度、重ね書き、余計な脱線を試せるようにする。
- ゲーム本体のUIや対戦状態に依存せず、採点ロジック単体の検証に使用できる構成にする。

### 検証ツールの目的

- 同じ形状を異なる速度・点密度でなぞった場合に、スコアが不自然に変動しないことを確認する。
- 始点や描画方向を変えても、形状が同じなら同等に評価されることを確認する。
- 紋章の書き忘れ、余計な線、複数周回、局所的な脱線が意図したとおりに減点またはNGになることを確認する。
- 70点台、80点台、90点台、100点近傍の難易度が想定どおりになるまで、採点定数を調整できるようにする。
- 検証ツールとゲーム本体で採点結果が一致することを確認する。採点処理は可能な限り共通コードとして切り出し、二重実装を避ける。

## 要求仕様

### 1. 入力ルール

- MouseDownで1ストロークの記録を開始する。
- MouseMotion中の座標を入力Polylineとして記録する。
- MouseUpでその時点までの軌跡を一度だけ採点する。
- MouseUp後に再度MouseDownして続きを描くことはできない。
- 途中でマウスボタンを離した場合は、その時点までの軌跡で採点する。
- 始点、終点、描画方向、描画速度、自己交差部分の通過順序は、形状評価の中心にしない。

### 2. Polyline前処理

- 目標紋章とユーザー軌跡を、連続した線分の集合として扱う。
- 生の入力点列をそのまま採点せず、極端な入力ノイズを除去する。
- 目標側・ユーザー側の双方を弧長ベースで一定間隔に再サンプリングする。
- 再サンプリング間隔は定数化し、描画速度やフレームレートによって採点が変わらないようにする。
- 入力点が少なすぎる場合は失敗とする。

### 3. 距離計算

- 点とPolylineの距離は、最近傍点との距離ではなく、各線分へのPoint-to-Segment距離の最小値で求める。
- Target → User距離を計算し、目標紋章の各地点がユーザー軌跡でカバーされているかを判定する。
- User → Target距離を計算し、ユーザー軌跡が目標紋章からどれだけ外れているかを評価する。

### 4. 未通過区間のNG判定

- Target → User距離が`NG_DISTANCE`以上となる区間を検出する。
- 距離超過が1サンプルだけ発生した場合は、入力ノイズとして即NGにしない。
- 距離超過が目標紋章上で`NG_GAP_LENGTH`以上連続した場合は、通常スコアを与えずNGとする。
- `NG_DISTANCE`、`NG_GAP_LENGTH`、再サンプリング間隔は調整可能な定数または設定値にする。

### 5. 距離誤差の統計

User → Target距離から、少なくとも以下を算出する。

- MeanError
- P90Error
- P95Error
- P99Error
- CoverageError（Target → User距離の分布から算出）

P90、P95、P99を用いて、軌跡の一部分だけ大きく外れているケースが高得点になりすぎないようにする。

### 6. 軌跡長の評価

- `TargetLength`と`UserLength`をPolyline長として算出する。
- `LengthRatio = UserLength / TargetLength`を算出する。
- 1.0付近を理想値とし、過度な重ね書き、往復、複数周回に対して減点する。
- LengthPenaltyは総合Errorに含める。

### 7. 正規化とスコア

- 距離誤差を紋章の基準サイズで正規化する。
- 総合Errorは、MeanError、P90Error、P99Error、CoverageError、LengthPenaltyを重み付けして算出する。
- スコアは単純な線形変換ではなく、指数関数などの非線形関数で0〜100点へ変換する。
- 高得点帯を厳しくするため、平均誤差・P95誤差・P99誤差に応じたスコア上限を設ける。
- スコアは最終的に0〜100へClampする。
- 目標バランスは以下とする。
  - 55〜69点: 普通に成功
  - 70〜79点: 上手い
  - 80〜89点: かなり上手い
  - 90〜94点: 超上級
  - 95〜99点: 異常に綺麗
  - 100点: 理論上ほぼ完全一致。通常操作では極めて出にくい

### 8. 円・閉曲線

- 円などの閉曲線は、開始位置を問わず評価できるようにする。
- 時計回り、反時計回りのどちらも同等に扱う。
- 始点と終点が一致しているかどうかだけを理由にNGにしない。
- 閉曲線を正確に複数周した場合は、距離誤差が小さくても軌跡長の超過で減点する。

## 想定する採点フロー

```text
MouseUp
  ↓
入力ノイズ除去
  ↓
目標・入力Polylineを弧長再サンプリング
  ↓
Target → User距離を計算
  ↓
連続Gapを検出
  ├─ Gapあり → NG
  └─ Gapなし
       ↓
User → Target距離を計算
       ↓
Mean / P90 / P95 / P99 / CoverageError
       ↓
軌跡長RatioとLengthPenaltyを計算
       ↓
総合Errorを正規化
       ↓
非線形スコア化
       ↓
高得点キャップ
       ↓
0〜100点
```

## 受け入れ条件

- 始点を変えて同じ円をなぞっても、始点位置だけで大きくスコアが変わらない。
- 時計回りと反時計回りで、形状が同じなら同等に評価される。
- 目標の一部を書き忘れた場合、連続Gapが閾値を超えればNGになる。
- 目標線上を正確に複数周した場合、距離誤差だけでは満点にならず、軌跡長超過で減点される。
- 目標から外れた余計な線を追加した場合、User → Target距離とLengthPenaltyの両方で減点される。
- 入力点の密度や描画速度を変えても、同じ形状ならスコアが大きく変動しない。
- 一部だけ大きく脱線した軌跡が、MeanErrorだけで80点以上にならない。
- なぞり中の線の内側がインナーグローの線色で表示される。
- なぞり中の線の外側が詠唱士のメインカラーである紫で表示される。
- なぞり線の基本太さが、表示中の紋章の線の太さと一致する。
- ゲーム本体とは別に検証ツールを起動し、円・星を表示して実際になぞれる。
- 検証ツールはMouseUp時にスコア、NG理由、距離統計、カバー率、軌跡長比を表示する。
- 検証ツール上で始点・終点・描画方向・入力速度・点密度を変えた比較ができる。
- 検証ツールの採点結果とゲーム本体の採点結果が同じ入力に対して一致する。
- MouseUp時に一度だけ採点され、既存のスキル発動・失敗クールダウン・ネットワーク上のホスト判定が維持される。
- 詠唱士の小技・大技の合格ラインは既存仕様との整合を確認し、必要なら仕様書に明記する。
- Godotをヘッドレス実行し、スクリプトエラーが発生しない。
- 実画面で円・星のなぞりを行い、入力軌跡、NG判定、スコア表示、成功時のスキル発動を確認する。

## 調整対象の初期値候補

```text
SAMPLE_INTERVAL = 2px
NG_DISTANCE = 20px
NG_GAP_LENGTH = 30px

Error =
    MeanError     * 0.40
  + P90Error      * 0.30
  + P99Error      * 0.15
  + CoverageError * 0.10
  + LengthPenalty * 0.05

Score = 100 * exp(-pow(normalizedError / SIGMA, SCORE_POWER))
```

上記の数値は実装後のプレイテストで調整する。特に、許容距離、連続Gap長、`SIGMA`、`SCORE_POWER`、高得点キャップの閾値を確認する。

## 実装時の注意

- 現在の大技に存在する始点・終点スコアは、始点・終点を評価しない方針と矛盾するため削除または置き換える。
- Target → Userのカバー判定も入力点との単純なPoint-to-Point比較にせず、ユーザーPolylineの線分距離を使う。
- クライアントから受信した軌跡を採点する場合も、ホスト側で同じ前処理・採点処理を実行する。
- 既存の課題座標系、描画座標系、ネットワーク送信座標系を統一したまま変更する。
- 採点定数と統計値は、後からプレイテストで調整できるようにまとめる。
