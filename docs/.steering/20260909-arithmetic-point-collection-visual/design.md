# 設計書

## アーキテクチャ概要

回収状態をゲーム状態の可変エンティティとして保持する。サーバー権威のシミュレーションが待機・飛行・到達時の加算を決定し、ローカル対戦も同じ時間遷移を実行する。クライアントはスナップショットを補間して描画する。

```text
デコイ破壊
  -> arithmetic_point_collections に回収状態を追加
  -> 1秒間は source_position で表示
  -> owner の現在位置を目標に飛行
  -> 到達: a += amount、状態を削除
```

## コンポーネント設計

### 1. MatchSimulation

**責務**:

- デコイ破壊時に回収状態を生成する。
- 各回収状態を更新し、到達時だけ所有者の係数を増やす。

**実装の要点**:

- 状態には一意な `presentation_id`、`owner_id`、`position`、`amount`、`wait_time`、`flight_elapsed` を含める。
- 飛行中の目標は更新時点の所有者位置とし、移動中の算術士にも追従させる。
- 回収状態を作るのは、既存の所有者以外によるデコイ破壊経路だけに限定する。

### 2. MatchProtocol / MatchPrototype

**責務**:

- スナップショットと補間対象に回収状態を含める。
- ローカル・オンライン双方で数値をワールド座標に描画する。

**実装の要点**:

- 固定UIは増やさず、可変個数の数値を既存のワールド描画で扱う。
- リセット時に回収状態をクリアする。

## データフロー

### デコイ破壊から強化まで

1. 相手の攻撃がデコイを破壊する。
2. サーバーまたはローカル対戦が `+0.1` の回収状態を破壊位置に作る。
3. 各状態は1秒待機後、現在の所有者位置へ飛行する。
4. 到達時に係数を `0.1` 増やし、HUDの `f(x)` が更新される。

## テスト戦略

### ユニットテスト

- 破壊直後は係数が増えず、回収状態だけが増える。
- 1秒待機後に飛行し、到達後にのみ係数が増える。
- 複数回収状態が独立した開始時刻を保つ。
- スナップショットと補間で回収状態を維持する。

### 統合テスト

- Godotヘッドレスでネットワークシミュレーションのテストを実行する。
- Godotヘッドレス起動でスクリプトエラーがないことを確認する。

## 依存ライブラリ

追加なし。

## 実装の順序

1. 権威シミュレーションとローカル対戦の回収状態・係数加算タイミングを実装する。
2. 専用サーバー同期とワールド描画を実装する。
3. テストとヘッドレス起動で検証する。
