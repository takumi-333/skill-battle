# 3キャラクター・ドット絵8方向スプライト実装 — 設計

## アセット構成

3キャラクターは、同じ形式の単一スプライトシートを使用する。

| 表示ID | ファイル | 内容 |
| --- | --- | --- |
| `typist` | `assets/characters/typist_pixel_8dir.png` | 打鍵者の試験シートを採用した64px・8方向シート |
| `arithmetician` | `assets/characters/arithmetician_pixel_8dir.png` | 算術士の64px・8方向シート |
| `chanter` | `assets/characters/chanter_pixel_8dir.png` | 詠唱者の64px・8方向シート |

各シートは512×320px、64×64pxセル、8列×5行、RGBA透過とする。列は `下 / 下左 / 左 / 上左 / 上 / 上右 / 右 / 下右`、行は `停止 / 歩行1 / 歩行2 / 歩行3 / 歩行4` で固定する。

## 生成・検査フロー

1. 算術士・詠唱者を、打鍵者と同じ斜め上見下ろし・真のドット絵・8列×5行の構図で生成する。
2. 会社員風・立ち絵風にならないこと、固定外見、8方向、4フレーム歩行が保持されることを確認する。
3. 背景が不透明な場合は、キャラクター輪郭を保つ外周連結の背景除去を行う。
4. 最近傍補間で512×320pxへ正規化し、全40セルが64×64pxの範囲に収まることとRGBA透過を検査する。
5. 採用した打鍵者の試験シートを最終名へコピーし、3シートを同じ形式で配置する。

## Godot描画

既存の待機PNGと横4フレーム歩行シートの事前読み込みを、3枚の8方向シートへ置き換える。`visual_id` から対応テクスチャを選ぶ方式は維持し、能力・課題の `character_id` には触れない。

### 方向の決定

プレイヤーの `facing` を45度単位へ丸め、列番号に変換する。角度の8区分と列番号は次の対応とする。

| 角度区分 | 方向 | 列 |
| --- | --- | --- |
| 0° | 右 | 6 |
| 45° | 下右 | 7 |
| 90° | 下 | 0 |
| 135° | 下左 | 1 |
| 180° | 左 | 2 |
| 225° | 上左 | 3 |
| 270° | 上 | 4 |
| 315° | 上右 | 5 |

停止中は行0、移動中は `1 + (経過時間 × 8fps を4で剰余した値)` の行を使用する。ソース矩形は `(列 × 64, 行 × 64, 64, 64)` とする。左右反転は行わない。

### 表示位置

描画矩形は64×64pxとし、プレイヤー位置を足元寄りの基準点として配置する。大判アニメ調素材向けに上方へ移していたHP・中断ゲージを、64pxスプライトの上に収まる位置へ戻す。集中・被弾の色調、攻撃範囲、HP・中断ゲージは引き続きスプライトの上へ重ねて表示する。

## 検証

- 各PNGの512×320px、RGBA、40セルを検査する。
- ロビーで3キャラクターを選んだとき、対応するシートが描画されることを確認する。
- 上下・左右・斜め移動ごとに正しい列が選ばれ、停止時は停止行、移動時は歩行行が切り替わることを確認する。
- スキル分岐・課題・ダメージ判定に関わる既存IDやロジックに変更がないことを確認する。
