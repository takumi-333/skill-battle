# 要求内容

## 概要

詠唱士のオンラインなぞり課題で、採点に関係しない入力時間・点数・軌跡長・点間距離の条件によって発動機会を失う問題をなくす。形状採点、サーバー権威の発動判定、正しい失敗時のNG表示と不発動は維持する。

## 背景

Dedicated Server は軌跡採点より先に `TRACE_MIN_ELAPSED`、`TRACE_MIN_POINTS`、`TRACE_MIN_LENGTH`、`TRACE_MAX_SEGMENT_LENGTH` で提出を失敗させる。これらは課題画面で案内されず、詠唱者仕様にある「距離・カバー率による評価」と「不合格時の赤表示」にもオンライン経路が揃っていない。

現行のプロトコルには送信上限512点があるため、クライアントが上限を超えた軌跡をそのまま送ると、サーバーが採点前にイベントを拒否して課題が残る可能性も扱う。

## 実装対象の機能

### 1. 入力条件と採点

- 描画経過時間、最小入力点数、最小軌跡長、最大点間距離による発動前の足切りをなくす。
- 入力形式・サイズなど通信保護に必要な検証とサーバー権威は維持する。
- 実際に受理した軌跡の形状を既存 `TraceEvaluator` で採点し、合格点に達した場合のみ従来の詠唱士スキル生成を呼ぶ。

### 2. 参加者向け結果表示

- 形状採点が不合格の場合は、参加者側の課題ウィンドウを赤く揺らし、ミス音を再生してから閉じる。
- 不合格では既存どおりスキルを発動せず、失敗クールダウンを適用する。
- 成功では従来どおり課題を閉じ、サーバーが確定したスキル実体を表示する。

### 3. 送信点数の上限

- 512点の通信上限を維持したまま、クライアント側で軌跡を上限内に整形し、正しい描画が上限超過によって無言で拒否されないようにする。
- 整形後の軌跡を画面表示と送信で共用し、クライアント表示とサーバー採点に異なる軌跡を使わない。

## 受け入れ条件

### サーバー判定

- [x] 4つの旧妥当性条件だけに該当する入力を理由に、サーバーが提出を不発動扱いにしない。
- [x] `TraceEvaluator` のNGまたは合格点未満は不発動・失敗クールダウンとなる。
- [x] 合格点以上の軌跡だけが、既存スキルID・スキル種別に対応する効果を一度だけ生成する。
- [x] 参加者スロットとホストスロットの両方で同じルールを使う。

### 結果UXと通信

- [x] オンライン参加者の形状採点失敗で赤表示・揺れ・ミス音を確認でき、失敗後に課題が閉じる。
- [x] 成功表示と失敗表示が同一結果の重複通知で二重実行されない。
- [x] 512点以内に整形された軌跡が送信され、点数上限に起因する無言のイベント拒否がない。
- [x] 最大長・型などプロトコル上の入力検証を維持する。

## 成功指標

- プレイヤーが通常のマウス操作で描いた軌跡は、形状採点の結果だけで発動可否が決まる。
- 発動しない場合、正当な形状採点不合格として赤いNG表示が見える。
- スキルの効果生成とクールダウンはサーバー権威で一貫する。

## スコープ外

- TraceEvaluator の採点式・合格点・紋章形状の変更。
- クライアント側だけでスキル成功を確定すること。
- 詠唱者以外の課題入力やスキル判定の変更。
