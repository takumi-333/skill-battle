# 要求内容

## 概要

Dedicated Serverを正としたまま、スキル演出の連続性、移動入力の安全性、なぞり課題の入力妥当性を改善する。ハンマー回転だけに特化せず、サーバーが保持する連続スキル実体をクライアントで滑らかに表示し、snapshotで補正する共通機構を作る。

## 実装対象

1. スキル発動時に一度だけ届くreliableな演出イベントを追加する。クライアントはこれを演出開始の契機とし、状態snapshotは位置・寿命・発動済み状態の補正に使う。
2. slotごとの移動入力に失効時間を設け、新しい移動入力を一定tick受け取れない場合はサーバーが停止入力へ戻す。
3. なぞり課題について、送信された軌跡の点数だけでなく、点間距離・軌跡全長・課題開始からの経過時間をDedicated Serverで検証する。
4. ハンマー回転を含む連続演出に固有IDとサーバーtickを付与し、クライアントが表示用に時間を進める。snapshot受信時は最短角度で補正し、回転角が0/2πをまたいでも逆回転・跳躍しない。

## 受け入れ条件

- [ ] スキル実体の生成時に、room内の各クライアントへreliableな演出イベントが一度だけ送られる。
- [ ] 演出イベントの重複・順序逆転をIDで無害化できる。
- [ ] snapshot未到達中も、連続演出はクライアントの描画時間で滑らかに進む。
- [ ] snapshotの到着時、角度は最短経路で補正され、0/2π境界で大きく逆回転しない。
- [ ] ダメージ、命中、スキル寿命、生成、ノックバック、勝敗はDedicated Serverだけが決定する。
- [ ] 移動入力が失効するとサーバー上の移動が停止する。
- [ ] 妥当性を満たさないなぞり軌跡は失敗となり、スキルを生成しない。
- [ ] 自動テストとGodotヘッドレス起動で確認する。

## スコープ外

- 近接攻撃の過去位置巻き戻し。
- 完全なクライアント予測・入力履歴再生。
- 高度なチート検出・外部不正対策。
