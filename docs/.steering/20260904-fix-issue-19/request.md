これがほかの２キャラでも起きる可能性はある。（未確認）

## 調査結果

### 原因

打鍵士スキル2の派生「鍵片追弾」で、課題種別の識別文字列と入力判定条件が一致していない。

`start_skill_challenge()` はこのスキルの課題を `big_typing_keycap_ii` と設定するが、タイピング入力の判定開始条件 `_is_typing_challenge()` は `challenge_skill.ends_with("typing")` になっている。

そのため `big_typing_keycap_ii` はタイピング課題として認識されず、課題ウィンドウは表示されるものの、入力を成功・ミスとして処理する `_process_typing_character()` が即時 return する。結果として、無効な課題ウィンドウが開いた状態になる。

### 影響範囲

- 打鍵士スキル2「鍵片追弾」：再現する
- 打鍵士スキル1：`small_typing` のため再現しない
- 打鍵士スキル2「三叉震槌」：`big_typing` のため再現しない
- 算術士：`arithmetic` 判定のため、同じ原因は確認できない
- 詠唱者：`trace` 判定のため、同じ原因は確認できない

スキル再発動時のクールダウン判定は存在しており、今回の主原因は再発動処理そのものではなく、`big_typing_keycap_ii` の課題種別判定不一致である。

### 修正方針

課題種別の判定をスキルIDの末尾文字列に依存しない形へ整理し、`big_typing_keycap_ii` もタイピング課題として扱う。
