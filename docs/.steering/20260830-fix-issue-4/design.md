# issue-4 修正設計

## 操作対象の選択

`match_prototype.gd` にデバッグ専用の `debug_controlled_player_id`（初期値1）を追加する。デバッグキャラクター選択画面に「P1を操作」「P2を操作」の切り替えボタンを配置し、選択状態を明示する。

`start_debug_match()` で選択値を保持し、デバッグ対戦中のローカル入力を次のように扱う。

- `update_player()` は、デバッグ時に選択対象だけキーボード移動を受け付ける。
- 非選択キャラクターは位置を維持するが、クールダウンなどの時間更新は継続する。
- 通常攻撃・スキル開始は、デバッグ時には選択対象だけがキー入力に反応する。
- 練習対戦とオンライン対戦は既存の入力分岐を維持する。
- 選択キャラクターがP2でも、課題入力は既存の `challenge_owner` とローカル入力の仕組みで操作できるようにする。

## デバッグHUD

既存の単一 `player_one_label` を、P1とP2の情報をそれぞれ表示できる2つのラベルへ拡張する。デバッグ時は両ラベルにキャラクター名、HP、集中状態、通常攻撃・スキル1・スキル2のクールダウンを表示する。選択中のキャラクターには「操作中」を付ける。

オンライン時は従来どおり自分の情報を表示し、練習時も現在の単一キャラクター表示を維持する。これにより issue-4 の変更範囲をデバッグモードに限定する。

## UI配置

デバッグ選択画面の開始ボタン上部に操作対象選択ボタンを横並びで配置する。`update_debug_selection_preview()` 相当の更新処理でボタンの文言・色を更新し、現在の選択がキャラクター選択と独立して確認できるようにする。

## 検証

- `rg` でデバッグ入力が `debug_controlled_player_id` に限定され、デバッグHUDが両プレイヤーを参照していることを確認する。
- `godot --headless --editor --quit` でスクリプトとシーンの読み込みを確認する。
- `godot --headless --quit-after 3` で起動時エラーを確認する。
- 可能であればGUIでP1操作／P2操作の切り替え、対戦中の入力対象、両キャラのHUD表示を目視確認する。
