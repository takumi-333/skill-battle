# 設計

## 方針

既存の `match_prototype.gd` にある課題フロー（集中、入力、成功／失敗、クールダウン、ネットワーク同期）を維持し、課題内容と表示レイアウトをデータ化する。課題中の失敗は課題終了ではなく、プレイヤーごとの残り時間を減らし、UIフィードバックを追加する。

## データ

- `ChallengeDefinition` に候補リスト、正答、制限時間なし設定を追加する。
- `SkillDefinition` に課題ウィンドウの位置・サイズを追加する。
- キャラクターごとのスキル定義を `match_prototype.gd` で生成し、打鍵者の候補ワード、算術士の15問、詠唱者の紋章種別を保持する。

## 課題UI

- キャラクターIDとスキル番号から課題定義を取得し、`challenge_panel` の位置・サイズを適用する。
- 打鍵者・算術士は表示中の `LineEdit` を常にフォーカスし、`_input` でも課題中の文字列を入力欄へ転送する。
- 入力ミス時は文字列をリセットせず、残り時間を大きく減らし、赤色フラッシュと短い振動を再生する。
- 詠唱者は時間経過による失敗を行わず、マウスボタンを離した時だけ軌跡を評価する。

## スキル効果

- 打鍵者スキル1は入力文字を0.5秒間隔の非追尾弾として順次生成する。スキル2は正面と±60度の3方向へ衝撃波を生成する。
- 算術士スキル1は周囲にデコイを生成し、個体ごとの揺動タイマーと本人向け透明度を管理する。スキル2は速度・攻撃力バフと透明化状態を管理する。
- 詠唱者スキル1は1.5秒間隔で3回の遅延範囲攻撃、スキル2は16方向弾を3周生成する。

## 互換性

既存のホスト権威判定、課題中断、割り込みゲージ、失敗クールダウン、勝敗処理を変更しない。ネットワーク状態には新しい効果の状態を含め、クライアント表示を同期する。
