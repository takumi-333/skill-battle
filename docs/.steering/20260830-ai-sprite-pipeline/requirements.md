# AIスプライト生成パイプライン — 要求

## 概要

AIが作る見た目と、ゲーム素材として必須のサイズ・位置・透過・配色・シート構造を分離する。AIには**1回につき1フレームだけ**を生成させ、個別に採用した40枚を決定論的に組版・検査してGodot用スプライトシートへ変換する。

## 背景

現行の制作ガイドはAIに8列×5行の完成シートを生成させ、後から分割・正規化する方式である。この方式は、AIがグリッド、セル境界、40フレームの整合性を同時に扱うため、壊れたセルや別人物化が発生しても原因を切り分けにくく、実際うまく生成できないケースがおおい。
追加キャラクターや新モーションを同じ品質で制作するには、失敗を1フレームに閉じ込め、手順と合格条件をコードで再現可能にする必要がある。

## 実装対象の機能

### 1. アセット仕様と生成履歴

- キャラクター／モーション単位で、出力寸法、グリッド、足元アンカー、許可パレット、必須・禁止の見た目、および40フレームの個別IDを定義するJSON仕様を置く。
- 採用候補の生成元、参照画像、プロンプト、モデル／seed、後処理、レビュー結果をmanifestとして記録する。
- 現行の世界観・キャラクター設定・制作ガイドを正とし、仕様ファイルはそれらを置き換えない。

### 2. 共通motion spec

- AI生成の前に、40フレームの位相・方向・足運び・体の上下動・足元／中心アンカーをmotion specとして確定する。
- `assets/motions/humanoid_walk_8dir.json` を共通の歩行骨格として用意し、キャラクターの外見とは分離する。
- motion specは将来、OpenPose、2D skeleton、Blender render、手描きsilhouetteなどのPose Guideを参照できる。

### 3. 決定論的アセットビルド

- 生成元の個別フレームを、1ファイルずつ最近傍補間で64×64pxへ正規化する。
- 各フレームの足元を指定アンカーへ揃え、指定された方向・行・列に機械的に配置してRGBA PNGの512×320pxシートを生成する。
- source imageがネイティブ透過か不透明かを判定し、必要時はalpha extraction／背景除去を行ってRGBA normalized frameを作る。
- 高解像度のsemantic renderは、pixelization、palette quantization、pixel cleanupを経てからアンカー正規化する。`NEAREST`は、確定済みpixel gridの拡大・縮小を壊さない用途だけに使う。

### 4. 自動検査と採用判定

- 寸法、RGBA、グリッド、各セルの非空、セル境界越境、透明背景、足元アンカー、パレット、命名規則を検査する。
- 検査失敗時は、どのフレーム・どの規則に違反したかを人が再生成指示へ使える形で出力する。
- 外見の同一性、歩行の自然さ、既存素材とのトンマナ、第三者IPとの類似リスクは人による最終確認とする。

### 5. Godotへの安全な受け渡し

- 検査済みのファイルだけを`assets/characters/<id>_pixel_8dir.png`へ昇格できるようにする。
- 表示用IDとゲームロジック用IDを分離する現在の構成を維持し、生成パイプラインはスキル・課題ロジックを変更しない。

## 受け入れ条件

### アセット仕様と生成履歴

- [ ] 追加キャラクターまたは追加モーション1件について、仕様JSONとmanifestを作成できる。
- [ ] 仕様JSONに512×320px、64×64px、8列×5行、方向・行順、足元アンカー、パレット方針を定義できる。
- [ ] manifestから生成に使った入力・設定・人間レビューの追跡ができる。

### 共通motion spec

- [ ] 40フレーム全件について、phase、direction、足運び、body bob、アンカーを機械可読に定義できる。
- [ ] 各frame IDをmotion spec内のPose Guideへ対応付けられる。

### 決定論的アセットビルド

- [ ] 40枚の個別生成フレームから、RGBAの512×320px・40セルの出力を再現可能に生成できる。
- [ ] 1フレームの不合格時に、他の39フレームを再生成・再加工せず差し替えられる。
- [ ] 全セルの足元が仕様で定めたアンカーに揃う。
- [ ] 生成モデルを変更しても、ビルド結果のファイル形式とGodot側の参照規約は変わらない。
- [ ] source imageが不透明でも、alpha extractionの結果・手法・閾値をmanifestに記録してRGBA normalized frameを作れる。
- [ ] high-resolution sourceを`NEAREST`だけで64pxへ間引かず、pixelization・palette quantization・cleanupを通す。

### 自動検査と採用判定

- [ ] 形式違反を終了コード非0で検出し、違反理由と対象フレームを出力する。
- [ ] 検査を通過しない素材は採用先アセットへ配置できない。
- [ ] 検査済み素材をGodotで読み込み、8方向の停止・歩行表示に使える。

## 成功指標

- 形式・透明度・ファイル名・グリッド・パレットのハードゲートは100%通過する。
- 足元アンカーの誤差は論理ピクセルで0.5px以下を目標にする。
- 人間レビューで、同一キャラクター性・歩行の読みやすさ・トンマナを各4/5以上とする。

## スコープ外

以下は初期導入では実装しない。

- LoRA学習、DreamBooth、専用GPUサーバー、ComfyUIの常設運用。
- AnimateDiffやSprite Sheet Diffusionによる時系列モデルの導入。
- 攻撃・被弾・スキル用アニメーションの仕様追加。
- AIによる外見同一性・権利侵害の自動合否判定。
- 既存3キャラクターのデザインまたはGodotのゲームロジック変更。
