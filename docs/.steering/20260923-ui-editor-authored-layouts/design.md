# 設計

## 方針

- `lobby_screen.tscn` の配下に `DuelLayout` と `FfaLayout` を置き、それぞれが必要なプレイヤーカード、プレビュー、情報、状態、選択ボタンをシーンノードとして保持する。
- `hud.tscn` の配下に `DuelLayout` と `FfaLayout` を置き、それぞれが自分と対戦相手のHP表示をシーンノードとして保持する。
- 両レイアウトをシーンファイルに保存し、片方だけを初期表示にする。GodotエディタではSceneツリーから可視性を切り替えて編集できる。
- スクリプトは対戦モードに応じてレイアウトルートの `visible` を切り替え、アクティブなレイアウト内の固定ノードを参照する。
- 名前、HP、Ready、画像、ボタンの利用可否などゲーム状態に由来する値だけを実行時更新する。
- 既存の `_apply_lobby_card_layout()` と `_set_lobby_rect()` は削除する。

## 互換性

- 共通のタイトル、開始、準備完了、ホーム操作はロビーの共通部品として維持する。
- スキルHUD、タイマー、操作説明など人数で配置を変えない部品はHUDの共通部品として維持する。
- レイアウト切替後に参照変数を再取得し、既存ロジックを再利用する。

## 検証

- シーンを読み込み、両レイアウトに固定ノードと仮表示値が存在することを確認する。
- 2人・3人のロビー更新で該当レイアウトだけが表示され、シーン保存座標が変わらないことを確認する。
- 2人・3人のHUD更新で該当レイアウトだけが表示され、対戦相手情報が更新されることを確認する。
