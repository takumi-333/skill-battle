# 設計

十六夜のサーバー判定弾は `MatchSimulation.state["skill_projectiles"]` に保持するが、`client_predicted` フラグを付与して専用クライアントへの個別同期対象から外す。

十六夜発動時に、所有者・得点・周回数・実際に生成された弾数を含む `chanter_skill3_volley` プレゼンテーションを1件キューへ追加する。`MatchSession` はこのキューを既存の reliable presentation RPC に載せ、`client_predicted` 弾の個別プレゼンテーションを抑止する。`MatchProtocol.snapshot()` も同フラグ付きの弾を除外する。

クライアントはこのプレゼンテーションを一度だけ受け取り、従来の十六夜と同じ4方向 × 16発 × 周回数、0.08秒間隔の視覚弾を、イベントに含まれる実弾数までローカル配列に生成する。発射時の所有者位置はクライアントが表示している所有者位置を用いるため、発射待機中の移動を見た目にも反映できる。視覚弾はダメージや衝突判定を行わず、寿命・場外で破棄する。

この方式はサーバー権威を維持しつつ、十六夜の最大256弾を20Hzで複製・送信・補間する経路だけを除去する。
