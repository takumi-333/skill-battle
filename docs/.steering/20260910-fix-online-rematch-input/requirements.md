# 要求内容

## 概要

オンライン対戦の再戦後、両プレイヤーが移動できなくなる問題を解消する。各試合の入力・イベント連番を、サーバーとクライアントで同じラウンド境界に同期させる。

## 背景

決着演出など試合外フェーズでクライアントとサーバーの連番がずれると、最大飛び幅の検証により新しい試合の入力が恒久的に拒否される。

## 実装対象の機能

### 1. ラウンド境界の連番同期

- Dedicated Server はカウントダウン開始ごとに入力・イベント連番を初期化し、ラウンドIDをsnapshotへ含める。
- Dedicated Client は新しいラウンドIDを受信した時点で送信連番と押下状態を初期化する。

### 2. 再戦回帰の防止

- 再戦後、連番1の移動入力とイベントがサーバーに受理され、移動状態へ反映されることをテストする。

## 受け入れ条件

- [ ] 再戦開始後の最初の移動入力が受理され、プレイヤー位置が変化する。
- [ ] 再戦開始後の最初の単発イベントが受理される。
- [ ] 再戦のsnapshotでラウンドIDが増加する。
- [ ] ネットワークシミュレーションテストが成功する。

## スコープ外

- Lobby APIの予約・再接続フローの変更。
- 従来のホスト方式のネットワーク経路の変更。
