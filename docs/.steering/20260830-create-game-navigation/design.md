# 実装設計

## 方針

現在は `MatchPrototype` が接続選択、ロビー、対戦、リザルトを単一シーン内で管理している。この構成を維持しつつ、画面遷移を明示する `screen` 状態を追加し、既存の `phase`（ロビー・カウントダウン・対戦・リザルト）および `network_mode`（ローカル・ホスト・クライアント）と役割を分離する。

タイトル、ホーム、オンライン接続、オンライン待機、練習選択、デバッグ選択をそれぞれ `Control` ベースのパネルとして生成する。対戦ロジックとネットワークRPCは既存実装を再利用し、画面側は選択値と開始要求を既存の `p1_selection` / `p2_selection`、準備状態、`begin_match()` に接続する。

## アーキテクチャ概要

```text
起動
  → TitleScreen
  → HomeScreen
      ├─ OnlineScreen（ルーム作成・参加）
      │   └─ OnlineWaitingScreen
      │       └─ 両者の準備完了 → countdown → match
      ├─ PracticeScreen
      │   └─ キャラクター選択 → practice match
      ├─ DebugScreen
      │   └─ 左右のキャラクター選択 → local debug match
      └─ Character（将来用。今回の遷移先は設けない）
```

- `screen` はメニューおよび開始前画面の表示を管理する。実装では`MatchPrototype`内に画面パネルを生成し、`title` / `home` / `connection` / `online_waiting` / `practice_select` / `debug_select` / `match`を切り替える。
- `phase` は試合開始後を含む対戦進行を管理する。`screen == "online_waiting"` の間は `phase == "lobby"` とする。
- ホストを試合・待機状態の権威とし、参加者の選択・準備操作は既存のRPCでホストに送信し、同期状態から表示を更新する。

## コンポーネント設計

### 1. 画面ナビゲーション

**責務**:

- 起動時にタイトルを表示し、入力でホームへ遷移する。
- ホームからオンライン、練習、デバッグの各開始画面へ遷移する。
- 現在の画面に必要なパネルのみを可視化し、対戦HUD・課題UI・リザルトUIとの重なりを防ぐ。

**実装の要点**:

- `MatchPrototype` にタイトル、ホーム、練習選択、デバッグ選択、オンライン待機用のパネル参照と、画面を切り替える共通メソッドを追加する。
- タイトル画面の `_input()` ではスペース、Enter、マウス左クリックを開始入力として扱い、キーのリピート入力は無視する。
- ホームの「キャラクター」は育成画面未実装であることを明示して無効状態または説明表示とし、未実装の画面へ遷移させない。
- タイトルロゴは `assets/ui/` 配下の透過PNGとして追加し、タイトル画面の `TextureRect` から表示する。ロゴ制作時は `imagegen` スキルを用い、文字が読み取れることを確認する。

### 2. オンライン接続・待機画面

**責務**:

- 既存のルーム作成、参加、IP:ポート入力をオンライン対戦画面として提供する。
- ホストと参加者に対応する左右の選択領域、相手の入室状態、準備状態を表示する。
- キャラクター選択と準備完了をネットワーク同期し、両者の準備完了で試合を開始する。

**実装の要点**:

- 既存の `network_panel` はオンライン接続画面として再配置・再利用し、作成・参加成功時にオンライン待機画面を表示する。
- 待機画面は、`p1_selection` / `p2_selection` に対応する立ち絵・表示名・左右切替ボタン・準備完了ボタンを持つ2つの選択領域で構成する。
- ホストは左領域だけ、クライアントは右領域だけを操作可能にする。ローカルモードの待機画面は使用しない。
- 接続済みかは `multiplayer` の接続状態をホスト側で判定し、未接続の相手領域には空欄、接続後は人影プレースホルダーまたは選択中の立ち絵を表示する。
- `receive_remote_lobby_choice()`、`make_network_state()`、`receive_network_state()` の既存同期経路を使い、必要であれば選択確定状態を追加する。ホスト側だけが両者の準備完了を判定し、`countdown` へ遷移する。
- 選択を変更した場合は、そのプレイヤーの準備完了を解除して選択内容と準備状態の不一致を防ぐ。

### 3. 練習・デバッグ開始画面

**責務**:

- 練習では操作キャラクター1名を選択し、相手のいない練習用対戦を開始する。
- デバッグではP1・P2を独立して選択し、既存の同一PC対戦を開始する。

**実装の要点**:

- 練習は `network_mode = "practice"` を追加し、P1だけを更新・描画する。既存の対戦計算は再利用し、練習画面では相手を表示しない。
- 練習開始時は選択内容をP1へ設定し、既存のキャラクター移動・通常攻撃・課題UIを利用する。相手プレイヤーは生成・入力・勝敗判定の対象外とする。
- デバッグは `network_mode = "local"` を使い、選択画面で設定した `p1_selection` / `p2_selection` により既存の `begin_match()` を呼び出す。
- 両画面とも、立ち絵、表示名、左右切替、開始ボタンの共通生成ヘルパーを用いて選択UIを実装する。

### 4. キャラクター選択データ

**責務**:

- 選択番号、内部キャラクターID、表示用ID、表示名、立ち絵を一元管理する。

**実装の要点**:

- `MatchPrototype` 内に重複している選択用配列を、選択情報を返すヘルパーへ集約する。
- 内部IDは既存どおり `blade` / `arithmetic` / `chanter`、表示用IDは `typist` / `arithmetician` / `chanter` を使用する。
- 立ち絵は `assets/characters/<visual_id>_idle.png` をプリロードし、オンライン待機・練習・デバッグの選択UIで共通利用する。仮タイトルロゴは`assets/ui/skill_battlers_logo.png`へ配置した。

## データフロー

### オンライン対戦開始

```text
1. ホームでオンライン対戦を選択する。
2. ホストはルーム作成、参加者はIP:ポートを入力して参加する。
3. 成功後、ホストは左、参加者は右の待機領域を表示する。
4. 各プレイヤーがキャラクターを選択し、選択番号と準備状態をホストへ送る。
5. ホストが状態を両者へ同期し、待機画面を再描画する。
6. ホストが両者の準備完了を確認し、既存のcountdownとbegin_match()を実行する。
```

### 練習・デバッグ開始

```text
1. ホームで練習またはデバッグを選択する。
2. 選択UIで1名、または左右2名のキャラクターを選ぶ。
3. 開始操作で選択番号を設定し、対応するモードを初期化する。
4. configure_player()で選択内容をプレイヤー状態へ反映し、対戦画面を表示する。
```

## エラーハンドリング戦略

- ルーム作成・参加に失敗した場合はオンライン接続画面を維持し、既存の接続エラー文言を表示する。
- クライアント切断時はネットワーク状態をリセットし、オンライン接続画面へ戻す。
- 無効な選択番号を受信した場合は、既存と同様に0〜2へクランプする。
- 参加者がいない状態でホストが準備完了しても、カウントダウンおよび試合開始は行わない。

## テスト戦略

### 手動確認

- 起動直後のタイトル表示と、3種の開始入力によるホーム遷移を確認する。
- ホームの各ボタンの配置・遷移・未実装キャラクター入口の扱いを確認する。
- ローカルのホスト・クライアント2プロセスで、入室表示、左右別の選択、選択変更時の準備解除、両者準備完了からの試合開始を確認する。
- 練習でP1のみを操作でき、相手不在でエラーなくスキル課題を利用できることを確認する。
- デバッグで各組み合わせを選択し、既存の同一PC対戦が開始できることを確認する。

### 回帰確認

- 既存のオンライン接続失敗・切断時の復帰、リザルトからの再戦・ロビー復帰を確認する。
- 通常のローカル対戦、オンライン対戦でHUD、課題、勝敗表示にエラーがないことを確認する。
- Godotを起動し、デバッガと出力ログにスクリプトエラーがないことを確認する。

## 依存ライブラリ

新規の外部ライブラリは追加しない。Godot標準の `Control`、`TextureRect`、`Button`、`Label` と、既存の高レベルマルチプレイヤーAPIを使用する。

## 実装の順序

1. タイトルロゴ素材を作成し、タイトル・ホーム画面と画面遷移を追加する。
2. 既存の接続画面をオンライン対戦画面へ整理し、立ち絵を使うオンライン待機画面と同期を追加する。
3. 練習およびデバッグの選択画面・開始処理を追加し、対戦モードの分岐を整備する。
4. ローカル・オンラインの動作とGodotログを確認し、必要な修正を行う。

## セキュリティ考慮事項

- クライアントから受け取るキャラクター選択値は0〜2に制限し、試合開始判定はホストだけが行う。
- 既存方針どおり、クライアントの準備状態・選択内容を信頼して直接試合状態を変更せず、ホストの同期結果を表示する。

## パフォーマンス考慮事項

- 立ち絵テクスチャは事前ロードして選択切替時のディスクI/Oを避ける。
- 待機画面の更新は既存のネットワーク同期間隔に従い、毎フレームRPCを送信しない。

## 将来の拡張性

- 選択情報を集約することで、キャラクター追加時は選択データと画像を増やすだけで各選択画面へ反映できるようにする。
- `screen` と `phase` を分離することで、将来のキャラクター育成画面、設定、マッチング画面を対戦進行ロジックから独立して追加できるようにする。
- タイトルロゴは最終版の画像に差し替え可能な単独アセットとする。
