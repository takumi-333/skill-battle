# 実装設計

## 方針

`docs/specs/キャラクター設定.md` から、打鍵者・算術士・詠唱者それぞれのデザイン契約を抽出する。立ち絵と8方向スプライトシートには同じ契約を明記して生成し、生成後はガイドに従って正規化・検査した素材だけを既存ファイルと置き換える。

ゲーム側にはすでに表示用IDとスプライトシートの参照、45度単位の方向変換、停止・歩行アニメーションの描画がある。そのため、素材が最終仕様を満たすかを確認した上で、参照コードを要件どおり再点検し、差異がある場合にだけ最小限の修正を行う。

## デザイン契約

| ID | 人物像と識別要素 | 配色・衣装 | 禁止・注意事項 |
| --- | --- | --- | --- |
| `typist` | 真面目で親しみやすい若い男性魔導学者。短く整えた黒髪、細い黒縁眼鏡。 | 白シャツ・暗色パンツ・深い緑の裏地を持つ短いコート、金または淡緑のルーン刺繍、革ベルト、小さな護符、淡い緑のルーンペンダント。 | 仕様にない武器を追加しない。現代の会社員だけに見える意匠にしない。 |
| `arithmetician` | 知的でスマートな成人男性魔導学者。肩までの流れのある暗色の髪、博士帽。 | 深い青または紺の仕立てのよいローブ、金のアクセント、幾何学・数式を連想させるルーン刺繍、小さな魔法具または護符。 | 仕様にない武器を追加しない。 |
| `chanter` | 華やかで上品な成人女性の魔法使い。豊富な装飾品。 | 紫の大きなローブ、袖・裾の金または淡色の装飾、髪飾り、耳飾り、ネックレス、指輪。仕様どおり豊かな胸元と谷間を表現する。 | 仕様外の武器を追加しない。ゲーム用として背景や文字を含めない。 |

## 素材制作・正規化

1. 各IDで、透過RGBA・全身・右向き3/4・正方形の立ち絵を生成し、`<id>_idle.png` として保存する。
2. 同じデザイン契約を文章で指定し、8列×5行・40フレーム・透明余白付きのピクセルアートスプライトシートを生成する。
3. 生成シートを8列×5行に等分し、各フレームの縦横比を維持して最近傍補間で64×64pxへ縮小する。足元をセル下端にそろえ、RGBAの512×320px PNGへ書き出す。
4. 検査に合格したものを `assets/characters/<id>_pixel_8dir.png` として配置し、同名の旧画像を置き換える。

## ゲーム表示

対象は `scripts/match_prototype.gd` の表示処理とする。

- `get_character_texture()` は `visual_id` の `typist` / `arithmetician` / `chanter` に対して各新スプライトを返す。
- `get_sprite_direction_column()` は画面座標の方向を、素材の列順（下・下左・左・上左・上・上右・右・下右）へ変換する。
- `draw_player()` は停止時に行0、移動時に `1 + floor(elapsed * 8) mod 4` の行を選び、64×64pxの矩形を `Color.WHITE` で描画する。
- `character_id` は能力・課題の内部ID、`visual_id` は外見選択として維持し、両者を混同しない。

## 検証

1. 画像ツールで全6ファイルの存在、PNG、RGBAを確認する。
2. 各スプライトが512×320pxで、40セルすべてに人物が収まり、セル外の混入や切れ端がないことを目視確認する。
3. 立ち絵とスプライトを比較して、デザイン契約と配色が一致することを確認する。
4. Godotを起動し、対戦画面で3キャラクターの方向、停止、歩行、色が正しいこと、およびエラーログがないことを確認する。
