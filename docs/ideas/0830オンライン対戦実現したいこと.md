# オンライン対戦について実現したいこと

## リモートでの対戦を可能に
AさんとBさんが別の端末PC,別の家にいても対戦できるようにしたい。
このアプリは、各端末に展開させるか、
どこかの無料のプラットフォームにデプロイさせておいてそこで各自開いて対戦できるようにしたい。

## マッチング機能
まずは、ルームに参加を押すと、
開かれているルームリストが見れるようにし、それでマッチングを実現したい

## 実現方針メモ（検討中）

### 目標

- 最初は、離れた場所にいる2人がPC版で1対1対戦できることを目標にする。
- IPアドレスの共有や各家庭でのポート開放をプレイヤーに求めない。
- ルームを作成し、公開されているルーム一覧から参加できるようにする。
- 少人数（2〜3人程度）の試遊を前提とし、初期は無料枠のサーバー利用も検討する。

### 推奨する構成

プレイヤーPCをホストにするのではなく、インターネット上の公開対戦サーバーを試合のホストとする。

```text
ゲームクライアント A ─┐
                       ├─ 公開対戦サーバー ─ 試合状態・判定を管理
ゲームクライアント B ─┘

ゲームクライアント ─ ロビーAPI ─ ルーム作成・一覧・参加を管理
```

- **公開対戦サーバー**: 移動、攻撃、HP、課題の成功／中断、勝敗を正として判定し、両クライアントへ同期する。
- **ロビーAPI**: ルーム名、作成者、参加人数、公開状態などを管理し、ルーム一覧を返す。
- **ゲームクライアント**: ロビーAPIから一覧を取得してルームを選び、公開対戦サーバーへ接続する。クライアントは入力を送り、最終判定はサーバーの結果を採用する。

この構成なら、家庭用ルーターのNATやCGNATの影響を受けにくく、ホストプレイヤーの切断によって試合全体が止まる問題も避けられる。

### 初期の配備案

- Linux VMを1台用意し、Godotの専用サーバーを常駐させる。
- 現在のENet通信を継続する場合は、VMのパブリックIPでUDPポート（現状は7000）を公開する。
- GodotはLinux上でヘッドレス／専用サーバーとして実行する。
- 少人数の試遊では、無料枠のVM（例: Oracle Cloud Always Free）を候補にできる。ただしアカウント確認、無料枠の空き不足、低利用時の回収、利用規約の変更には注意する。
- 最初は独自ドメインやデータベースを必須にせず、対戦サーバーへ2人が接続できることを確認する。その後、ロビーAPIとルーム一覧を追加する。

### 実装を進める順番

1. ローカルPC上で、専用サーバーとゲームクライアント2個を分けて起動できるようにする。
2. 試合の権威をプレイヤーホストから専用サーバーへ移し、サーバー自身はプレイヤーとして扱わないようにする。
3. Linux VMに専用サーバーを配置し、異なるネットワークのPC 2台から接続して検証する。
4. ロビーAPIを追加し、ルーム作成・一覧取得・参加・満室・切断時の削除を実装する。
5. 必要に応じて、非公開ルーム、招待コード、ログイン、観戦、複数同時ルームへ拡張する。

### 現状との差分

現在は、プレイヤーがENetのホストを作成し、参加者がIPアドレスとポートを直接入力する試作方式である。試合同期の基礎はあるが、公開サーバー、ルーム一覧、接続先の解決、切断管理、認証は未実装である。

また、現在の構成は2人対戦を前提としている。3人目を観戦者にする、または複数ルームを同時に動かす場合は、接続人数と試合管理を追加設計する。

### ブラウザ版について

現在のENet（UDP）方式はPC向け配布に適している。ブラウザから直接遊べる形にする場合は、WebRTCまたはWebSocketを前提とした通信方式、シグナリングや中継の仕組みを別途検討する。したがって、初期段階ではPC版の公開サーバー対戦を優先する。
