# Photon Fusion移行判断

作成日: 2026-09-20

## 結論

**現行の「Photon Cloud中継 + 自PC上の審判（Master Client）」構成へ、対戦中のリアルタイム通信を全面移行することは厳しい。**

特に、移動・スキル・タイピングの即時性がゲーム体験の中心である本作では、専用サーバーをPhoton Cloud近傍へ配置できない限り、従来の審判ホストへの直接UDP通信と同水準の操作感を安定して得ることは難しい。

これはPhoton Fusion自体が使えないという意味ではない。ルーム発見、招待、接続情報の交換など、対戦本体の低遅延性を要求しない用途には利用余地がある。ただし、対戦中の権威入力・状態同期・タイピング確定をCloud中継に委ねる方針は採用しない。

## 根拠

### 実測結果

同一PC上で審判1台とPlayer 2台を起動し、Photon Cloudを経由して対戦した。審判プロセスで取得した代表値は以下のとおり。

| 区間 / 処理 | p50 | p95 | p99 | 評価 |
| --- | ---: | ---: | ---: | --- |
| Player入力 → 審判到達 | 54ms | 69ms | 84ms | 到達時点で操作感に影響する遅延 |
| Playerイベント → 審判到達 | 99ms | 119ms | 131ms | スキル・タイピングには大きすぎる遅延 |
| 入力処理 | 0.01ms | 0.05ms | 0.08ms | 問題なし |
| イベント処理 | 0.12ms | 0.23ms | 0.42ms | 問題なし |
| スナップショット生成・送信 | 0.19ms | 0.36ms | 0.46ms | 問題なし |
| スナップショット圧縮 | 0.12ms | 0.29ms | 0.39ms | 問題なし |
| 審判フレーム時間 | 16.67ms | 16.67ms | 約18ms | 継続的な処理落ちはない |

同一PC上のPlayerと審判であっても、通信は `Player → Photon Cloud → 審判PC` を通る。そのため、ローカルプロセス間通信のようにはならず、入力が審判へ届くまでに中央値54ms、イベントでは中央値99msを要している。

### 状態反映にはさらに待ち時間が重なる

審判で受けた入力・イベントは、20Hzの状態同期で次のスナップショットを待ってから、`審判PC → Photon Cloud → Player` の経路で返る。20Hz同期の待ち時間は平均約25ms、最大50msである。

Player側の復路計測を加えて最終確認する必要はあるが、審判側の実測だけでも、状態確定までの体感遅延は以下の水準になると見込まれる。

- 移動の権威状態反映: おおむね130ms以上
- スキル・タイピングの確定反映: おおむね180ms以上。悪いケースでは200ms超

この遅延は、スキル発動時に遅く感じること、正しいタイピングでも確定が遅れることと整合する。

### CPU・シリアライズは主因ではない

入力処理、イベント処理、スナップショット生成・圧縮はいずれもp99で0.5ms未満、審判のフレーム時間もほぼ60fpsを維持している。したがって、現時点の大きな遅延を圧縮形式・差分同期・ゲームシミュレーションのCPU最適化だけで解消することはできない。

### 専用サーバーを置けない制約

Photon Cloud近傍に専用審判を置けば、現在の「Cloudから自宅PC審判へ戻る」余分な区間を減らせる可能性がある。しかし専用サーバーを運用しない前提では、この改善策は取れない。

入力予測、即時UI、イベント予測を大規模に実装すれば、自分自身の見た目の反応は改善できる。一方で、相手への反映、権威側の確定、予測不一致時のロールバックは残る。タイピングのように判定確定が本質の操作では、複雑さに対して十分な改善にならない。

## 今後の方針

- 対戦本体は、以前成立していた「Player → 審判ホスト」への直接UDP通信方式を基本とする。
- NAT越え不能時だけリレー・トンネルをフォールバックとして利用する。
- Photonを残す場合は、対戦本体の中継ではなく、ルーム・招待・接続情報交換などの補助用途に限定する。
- Photon Player側の `PHOTON_PERF` ログも取得し、今回の判断を補強する。ただし、審判側実測だけで全面移行を継続しない判断には十分な根拠がある。
