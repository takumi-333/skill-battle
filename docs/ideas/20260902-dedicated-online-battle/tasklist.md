# タスクリスト

この計画は、実装開始時にモード2で進捗を更新しながら実施する。以下の順序は、専用サーバー対戦がローカルで成立してから外部VMへ進むようにしている。

## フェーズ1: 試合ロジックの専用サーバー化

- [ ] 現行のネットワーク処理と試合ロジックを棚卸しする。
  - [ ] `match_prototype.gd` のUI・描画・ローカル入力依存を一覧化する。
  - [ ] 既存のRPCごとに送信者、信頼性、検証する値を定義する。
- [ ] UIに依存しない `MatchSimulation` を実装する。
  - [ ] 移動、攻撃、スキル、課題、ダメージ、勝敗の状態更新を移す。
  - [ ] 60Hz tickと20Hzスナップショットを定義する。
  - [ ] 入力値、行動連番、可変長課題入力をサーバー側で検証する。
- [ ] `MatchSession` とヘッドレスの `DedicatedServer` を実装する。
  - [ ] room ID、2人のslot、peer ID、切断状態を管理する。
  - [ ] ルーム単位で状態を同期し、終了したroomを解放する。
  - [ ] Linux Dedicated Server用の起動シーンとエクスポート設定を追加する。
- [ ] クライアントを専用サーバー入力方式へ移行する。
  - [ ] オンライン時の両プレイヤーを共通の入力送信経路にする。
  - [ ] サーバースナップショットの補間表示と接続・切断表示を更新する。
  - [ ] 既存のローカル対戦・練習モードを回帰確認する。

## フェーズ2: ローカル統合検証

- [ ] 自PCで専用サーバーとクライアント2個を別プロセスで起動する手順を追加する。
- [ ] 90秒試合の開始、課題、勝敗、リマッチを統合テストする。
- [ ] 待機中・試合中の切断、無効な入力、満室をテストする。
- [ ] Godotをヘッドレスで実行し、パース・実行ログにエラーがないことを確認する。

## フェーズ3: ロビーAPIとルーム一覧

- [ ] FastAPIとSQLiteでロビーAPIを実装する。
  - [ ] room作成、一覧、参加予約、状態通知、health checkを実装する。
  - [ ] 2人定員の原子的な予約と60秒の予約失効を実装する。
  - [ ] 短命参加トークンの発行・署名検証を実装する。
- [ ] 専用サーバーとロビーAPIを連携する。
  - [ ] 入室時のトークン検証とslot割当を実装する。
  - [ ] 試合開始、切断、終了をAPIへ通知する。
- [ ] Godotクライアントのルーム一覧UIを実装する。
  - [ ] ルーム名での作成、一覧更新、選択、参加を実装する。
  - [ ] API／UDPの失敗、満室、期限切れを表示して安全に戻れるようにする。

## フェーズ4: OCI VMと運用

- [ ] Oracle Cloud Always FreeのArm VMを作成する。
  - [ ] ホームリージョン、2 OCPU、12GB、ストレージ合計200GB以内を確認する。
  - [ ] UDP 7000、TCP 443、限定したTCP 22だけをOCIとUFWで許可する。
  - [ ] SSH鍵、非root管理者、パスワードSSH無効化、自動セキュリティ更新を設定する。
- [ ] Linux用のサーバー成果物とロビーAPIを配備する。
  - [ ] systemdサービス、環境ファイル、Caddy設定、DBバックアップを追加する。
  - [ ] リリース、ロールバック、ログ確認、再起動の運用手順を文書化する。
- [ ] VM上で外部ネットワークから接続確認を行う。
  - [ ] 別ネットワークのPC 2台でルーム作成から試合終了まで確認する。
  - [ ] VM再起動後の自動起動とログを確認する。

## フェーズ5: 負荷・セキュリティ検証

- [ ] 10ルーム・20接続の疑似負荷試験を実装・実行する。
  - [ ] CPU、メモリ、tick遅延、ネットワーク量、状態同期遅延を記録する。
  - [ ] 基準を超えた場合は同時ルーム上限を実測値に変更する。
- [ ] UDPとHTTPの異常系、入力頻度制限、トークン漏えい耐性を確認する。
- [ ] Godotの実行ログ、APIテスト、静的検査、Linuxサーバー起動を最終確認する。
