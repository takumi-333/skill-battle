# スプライト素材作成ガイドライン

## 目的と対象

本書は、打鍵士の8方向移動スプライトを試作した際に実施した工程を、今後のキャラクター・モーション素材へ再利用できる手順としてまとめたものである。

画像の見た目・キャラクター設定は[キャラクターアセット制作ガイド](キャラクターアセット制作ガイド.md)および`docs/specs/`を正とする。本書は、AI生成を含む素材制作の工程、品質ゲート、保存先の扱いを定める。

## 結論

AIに完成スプライトシートを描かせない。**1回の出力は1フレーム、生成時に与える情報はシーケンス全体**とする。

```text
デザイン契約・asset spec・motion spec
                ↓
不変の主参照 + 指定Pose Guide
                ↓
AIが1フレームを生成
                ↓
透過処理・pixelization・アンカー正規化
                ↓
40枚をプログラムで組版・検査
                ↓
人間レビュー後に採用素材へ昇格
```

AIは外見・ポーズ・細部を描く。セルサイズ、透過、パレット、足元位置、シートの配置、検査はツールが担当する。この責務分離により、AIがグリッドやレイアウトを崩す問題を避ける。

## 今回の打鍵士パイロット

| 項目 | 実施内容 |
| --- | --- |
| 対象 | 打鍵士の8方向・停止＋歩行4位相、40セルシート |
| 既存素材の扱い | 既存シートを分割して参照画像と停止8フレームに再利用 |
| AI生成 | 歩行4位相×8方向の32フレーム候補を1枚ずつ生成 |
| 主参照 | 元の打鍵士スプライト、方向別参照、スタイル参照、motion spec／Pose Guide |
| 後処理 | alpha抽出、64px論理グリッド化、最大32色への量子化、足元・中心揃え |
| 組版 | 64×64pxセル、8列×5行、512×320px RGBA PNG |
| 機械検査 | サイズ、RGBA、空セル、足元アンカー、占有率 |
| 結果 | 候補シートは機械検査を通過。比較のため一時差し替え後、フレーム間の外見揺れが残るため元素材へ復元 |

この試作で得た重要な判断は、**機械検査の通過は採用判断ではない**という点である。座標や透過が正しくても、髪型・武器・衣装の形状がフレーム間で揺れれば、歩行アニメーションとしては採用しない。

## 作成手順

### 1. デザイン契約を固定する

世界観・キャラクター設定・既存ゲーム内素材から、各フレームで変えてはいけない要素を決める。

- 髪型・髪色・体格・衣装の大きなシルエット
- 武器・象徴物・配色・金具などの固定小物
- 禁止する背景、床、影、文字、別武器、別キャラクター要素
- 既存スプライトと揃える頭身、占有率、輪郭、ドット密度、明度帯

既存のゲーム内スプライトがある場合は、立ち絵よりもそちらを主な見た目の基準にする。

### 2. 40フレームのmotion specを先に決める

生成前に、方向と歩行位相を確定する。今回の共通定義は`assets/motions/humanoid_walk_8dir.json`である。

- 列: 下 / 下左 / 左 / 上左 / 上 / 上右 / 右 / 下右
- 行: 停止 / 歩行1 / 歩行2 / 歩行3 / 歩行4
- 各フレーム: 位相、方向、左右の足、body bob、足元アンカー、Pose Guide
- 足元アンカー: 64pxセル内の`x=32, y=56`

AIに「歩いている2枚目」を解釈させず、「このPose Guideを、このキャラクターとして描く」と指示する。Pose Guideは将来、OpenPose、2Dスケルトン、Blenderレンダリング、手描きシルエットに差し替えられる。

### 3. 不変の主参照を用意する

すべてのフレームで、同じ主参照を使う。

```text
Character Master      主参照: キャラクターの同一性
Direction Reference   主参照: その方向から見た外見
Style Reference       主参照: ドット密度・輪郭・配色
Pose Guide            主参照: 当該フレームの姿勢
Neighboring Frame     任意の二次参照: 微細な連続性だけを補助
```

`walk_01 → walk_02 → walk_03`のように、前フレームを次フレームの主参照にする連鎖は禁止する。小さな形状崩れが次フレームへ増幅するためである。隣接フレームは補助にとどめ、必ずCharacter MasterとPose Guideへ戻る。

### 4. 1フレームずつ候補を生成する

生成器へ渡す要求は、完成シートではなく1フレームである。

```text
Asset type: one production 2D game-character animation frame, not a sprite sheet
Inputs: Character Master, Direction Reference, Style Reference, Pose Guide
Request: <frame ID>のPose Guideを取る、デザイン契約を保った1人のキャラクター
Camera: 3/4 top-down view; head, shoulders and feet visible
Constraints: centered, feet near the ground anchor, no background/floor/shadow/text/grid
```

生成画像はRGBAであると仮定しない。不透明画像だった場合に備えて、出力画像と処理方法を記録する。

### 5. 透過処理とpixelizationを行う

今回の処理は次の順序である。

1. `extract_alpha.py`で既存alphaを保持する。alphaがなければ、四隅の背景色を使ったchroma keyで背景を抜く。
2. `pixelize_frame.py`でalpha閾値後の可視前景bboxを取得し、asset specの目標可視高さへ正規化して64×64pxの論理グリッドへ収める。半透明の縁や背景ノイズはbboxに含めない。
3. 高解像度からの縮小には`LANCZOS`を使い、その後に最大32色へ量子化する。
4. alphaの小さなノイズを閾値で除去し、必要なら目視で最小限のpixel cleanupを行う。

`NEAREST`を高解像度の生成画像から64pxへ落とす用途には使わない。これはpixel art化ではなく単なる間引きになり、輪郭欠損やランダムなノイズにつながる。`NEAREST`は、すでに確定したpixel gridを再配置・拡大縮小するときだけ使う。

打鍵士パイロットでは、既存採用素材の可視高さが55〜57pxだったため、目標値を56px、許容差を±3pxとした。前回の候補は歩行行だけ34〜46pxだったが、閾値後bboxによる再処理で歩行32枚を56〜57pxへ揃えられた。キャラクターごとにこの値をasset specの`normalization`へ記録し、停止・歩行で異なる縮尺処理を混在させない。

### 6. 40枚を正規化して組版する

`build_sprite.py`は各フレームのalpha bboxから中心Xと下端を計測し、全フレームを同じ足元アンカーへ移動してから組版する。

```text
target center X = 32
target ground Y = 56

[down] [down_left] [left] [up_left] [up] [up_right] [right] [down_right]
   idle
  walk_01
  walk_02
  walk_03
  walk_04
```

AIに位置合わせを任せず、ツールが64×64px・8列×5行・512×320pxという規格を保証する。

### 7. 検査と人間レビューを分ける

`validate_sprite.py`で次のハード制約を検査する。

- RGBAであること
- 512×320pxであること
- 40セルすべてが空でないこと
- 各セルの足元がアンカーに揃うこと
- 各セルの可視高さがasset specの目標値・許容差に収まること
- 前景の占有率がasset specの範囲に収まること

次に、人が以下を確認する。ここを通らない限り採用しない。

- 全方向・全位相で同じ人物に見えるか
- 髪、衣装、武器、装飾がフレーム間で変形・欠落していないか
- 歩行ループに不自然な揺れや跳ねがないか
- 既存キャラクター素材と並べたときに頭身・密度・色が浮かないか
- 意図しない第三者作品への類似がないか

### 8. 採用・復元

候補をゲームへ反映する前に、既存の採用素材をバックアップする。`promote_sprite.py`は検査成功時だけ候補を採用先へコピーする。

打鍵士パイロットでは、候補を比較用に一時差し替えした後、元素材をバックアップから復元した。候補・中間画像・検査レポートはローカルに保持し、削除しない。

## 使用ツール

| ツール | 役割 |
| --- | --- |
| `tools/extract_sheet_frames.py` | 既存512×320pxシートを64pxの個別参照フレームへ分割 |
| `tools/extract_alpha.py` | alpha保持または単色背景のchroma key |
| `tools/pixelize_frame.py` | 64px論理グリッド化、パレット量子化、alphaノイズ除去 |
| `tools/build_sprite.py` | アンカー揃えと40フレームの組版 |
| `tools/validate_sprite.py` | ハード制約の検査とレポート出力 |
| `tools/promote_sprite.py` | 検査済み候補だけを採用先へコピー |

代表的な実行順序は次のとおりである。`<asset-id>`と各パスは対象に合わせて置き換える。

```text
python tools/extract_sheet_frames.py --sheet <existing-sheet> --motion <motion.json> --output-dir <reference-dir>
python tools/extract_alpha.py <source.png> <rgba.png>
python tools/pixelize_frame.py <rgba.png> <frame.png>
python tools/build_sprite.py --spec <asset-spec.json> --motion <motion.json> --frames-dir <frames-dir> --output <candidate-sheet.png> --report <build-report.json>
python tools/validate_sprite.py --spec <asset-spec.json> --input <candidate-sheet.png> --report <validation-report.json>
python tools/promote_sprite.py --spec <asset-spec.json> --input <candidate-sheet.png> --target assets/characters/<id>_pixel_8dir.png
```

## 保存先とGit／Godotの扱い

次の4ディレクトリは生成作業用のローカル領域であり、GitとGodotから除外する。

```text
assets/generated/   生成画像・中間画像・候補シート・検査レポート
assets/manifests/   生成条件・レビュー・採用履歴
assets/motions/     生成用motion spec・Pose Guide定義
assets/specs/       生成用asset spec
```

各ディレクトリの`.gdignore`はGit管理し、内容だけを`.gitignore`で除外する。採用済み素材は`assets/characters/`へ、正式に残す仕様は`docs/specs/`へ、処理ツールは`tools/`へ置く。
