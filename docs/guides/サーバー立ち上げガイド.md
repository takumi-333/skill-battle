# Windows公開対戦の運用

## 公開開始

以下のコマンドは、このリポジトリのルートディレクトリで開いたPowerShellにそのまま貼り付けて実行します。管理者権限が必要な手順には、その旨を明記しています。

### 1. 公開サーバーを立ち上げる

標準ユーザーのPowerShellで、Lobby、Public Gateway、Dedicated Serverを起動する。

```powershell
.\deploy\windows\start-public.ps1
```

### 2. 公開経路を立ち上げて確認する

playit.gg agentを起動し、UDP tunnelの転送先が **`127.0.0.1:7000`** だけであることをdashboardで確認する。agent／tunnelの起動・停止はこのリポジトリのスクリプト管理外である。

次に、管理者として開いたPowerShellで、FunnelをPublic Gatewayへ設定する。この操作は `HTTPS :443`（必要なら8443/10000）を **`http://127.0.0.1:8080`** だけへ向ける。Lobbyの8000番へ向けてはならない。

```powershell
.\deploy\windows\configure-funnel.ps1
```

PowerShellで、公開前提条件と稼働状態を確認する。

```powershell
.\deploy\windows\check-public-prerequisites.ps1
.\deploy\windows\status-public.ps1
```

Funnel targetが`127.0.0.1:8080`であること、3プロセスが稼働中であること、Lobby/Gateway双方のloopback `/healthz`が200でGateway経由の`protected_api_ready`が`true`であることを確認する。外部回線でGatewayの`/healthz`、招待token付きの作成・一覧・参加を確認する。

### 3. クライアントをビルドし、友人に配布する

標準ユーザーのPowerShellでWindowsクライアントの配布ZIPを作成する。ZIPは `build\releases` に出力される。

```powershell
.\deploy\windows\build-client-release.ps1
```

作成されたZIPを友人へ送る。続けて、次のコマンドを実行して表示される **Lobby HTTPS URL** と **Shared invite token** を、ZIPとは別の連絡手段で送る。コマンド実行時に、公開したFunnelのHTTPS URLを貼り付ける。

```powershell
$lobbyUrl = Read-Host 'Funnel の Lobby HTTPS URL を貼り付け'
.\deploy\windows\show-client-invite.ps1 -LobbyUrl $lobbyUrl
```

友人はZIPを展開して `SkillBattle.exe` を起動し、ユーザー設定へ表示されたURLとtokenを入力する。`public.env` 全体、管理token、internal token、署名用secretは配布しない。

Funnelは公開reverse proxyであって認証境界ではありません。URL・shared invite tokenを知る第三者を想定し、tokenは必要な友人だけに送ります。`/admin`、`/admin/api/*`、`/internal/*`、`:8000`、SQLiteファイルは公開対象外です。

## 停止・障害対応

公開を止める順序は必ず次のとおりです。

1. **HTTP ingressを止める:** 管理者として開いたPowerShellでFunnelを停止する。

   ```powershell
   .\deploy\windows\stop-funnel.ps1
   ```

2. **UDP ingressを止める:** playit.gg dashboardまたはagent側で対象tunnelを停止する。
3. 両方がOFFと確認してから、標準ユーザーのPowerShellでローカルプロセスを停止する。これはGateway、Dedicated Server、Lobbyを停止するだけで、tunnelを停止しない。

   ```powershell
   .\deploy\windows\stop-public.ps1 -IngressAlreadyDisabled
   ```

`tailscale funnel --bg` は再起動後も設定を保持し得ます。3プロセスが停止しているだけで公開停止と見なさず、毎回Funnelとplayit.ggを確認してください。不審なアクセス、秘密値漏えい、公開先の異常を検知した場合は、まず上の1と2でingressを遮断します。続いて`public.env`の4 secretをすべて新しい暗号学的乱数へ置換し、Funnel URLとplayit.gg tunnel、共有先を見直してから再公開します。旧shared invite tokenと旧internal tokenはローテーション後に拒否されます。
