# 8方向スプライト素材作成フロー

本書は、[ガイドライン](8方向スプライト素材作成ガイドライン.md)で定めた完成条件を満たすための作業手順である。各コマンドの入出力と責務は[ツール一覧](ツール一覧.md)を正本とする。

## 作業の全体像

```text
事前準備
  ↓
フレーム単位: 生成・候補選定 → 背景除去 → 正規化・pixelization
  ↓
シート単位: 組版 → 自動検査 → 人間レビュー → 履歴記録 → 採用
```

フレーム単位の作業と、40フレームが揃ってから行うシート単位の作業を混ぜない。これにより、不具合があったときに必要なフレームだけを修正できる。

## 0. 事前準備

1. キャラクター設定、既存素材、asset spec、motion specを確認する。
2. asset specにセル・シート構成、アンカー、正規化条件、固定パレット、例外を記録する。
3. motion specに40フレームのID、方向、位相、必要なroot・接地情報を記録する。
4. Character Master、Direction Reference、Style Reference、各フレームのPose Guideを用意する。
5. `work/<character-id>/` に、`reference/`、`raw/`、`rgba/`、`frames/`、`reports/`を用意する。

## A. フレーム単位で制作する

各 `frame ID` について、次の手順を繰り返す。

1. Character Master、該当方向のDirection Reference、Style Reference、該当Pose Guideを入力して高解像度候補を生成する。全フレームで同じCharacter Masterと生成設定を使い、ローカル生成では共通seed bank、クラウド生成では共通Master Referenceを継続する。背景・床・影・文字は要求しない。
2. 向き、ポーズ、服・髪・武器の特徴が参照に合う候補を残す。候補の採否は最終的に40フレームの系列として比較するため、この時点で余白、足元位置、画像全体の大きさは判定しない。
3. 選んだ候補を `raw/<frame-id>/` に残し、背景を除去して `rgba/<frame-id>.png` を作る。
4. alpha閾値後の前景bboxを使い、asset specの正規化条件で `frames/<frame-id>.png` へ正規化・pixelizationする。固定パレットへのexact remapとalphaの二値化もこの工程で行う。
5. 出力した64×64px画像を確認する。足元以外の半透明ノイズや武器のはみ出しが残る場合は、シート化前に除去する。

個別フレームを手作業で `x=32, y=56` に置く必要はない。セル内のroot／足元を揃えるのは、シート組版時の責務である。

## B. シート単位で検査・採用する

1. `frames/` にmotion specの全40 IDが存在することを確認する。
2. 候補シートを作成する。build reportに、各フレームのrootまたはfallback anchor、移動量、bbox、接地点を残す。
3. 候補シートを自動検査する。失敗した場合はレポートの `frame ID` に戻り、該当フレームだけを修正して再作成する。
4. 自動検査に合格した候補を、等倍、4倍nearest、通常速度、0.25倍、ループ、シルエット表示で確認する。
5. 生成器・モデル・プロンプト版・参照素材の出所・パレット・レビュー結果を `manifest.json` に記録する。
6. 自動検査と人間レビューの両方に合格した候補だけを採用する。

## 差し戻しの判断

| 問題 | 戻る工程 |
| --- | --- |
| 透明背景、半透明ノイズ、不要な残留画素 | A-3 |
| 身体サイズ、横幅、パレット、alpha | A-4 |
| ポーズ、向き、顔・服・武器の不一致 | A-1 |
| root、接地、セル内の位置 | B-2の入力となるmotion specまたは個別フレーム |
| 歩行の連続性、同一性、ループ | 該当フレームのA-1 |

40フレームすべてを再生成するのは、Character MasterまたはStyle Referenceそのものが誤っていた場合だけとする。既存候補で足元が揃っている一方で人物だけが小さい場合は、再生成の前に元RGBA画像をasset specの正規化条件で再pixelizationする。

## 実行順の例

以下は `down_walk_01` を処理し、40フレームが揃った後にシート化する例である。

```text
# A-3: 選んだAI候補から背景を除去する
python tools/extract_alpha.py work/<character-id>/raw/down_walk_01/candidate_01.png work/<character-id>/rgba/down_walk_01.png

# A-4: 閾値後のbboxで64×64pxへ正規化・pixelizationする
python tools/pixelize_frame.py work/<character-id>/rgba/down_walk_01.png work/<character-id>/frames/down_walk_01.png --spec <asset-spec.json> --alpha-threshold 8 --content-height 56 --max-visible-width 60

# B-2: 全フレームが揃った後に候補シートを作る
python tools/build_sprite.py --spec <asset-spec.json> --motion <motion.json> --frames-dir work/<character-id>/frames --output work/<character-id>/<character-id>_candidate.png --report work/<character-id>/reports/build.json

# B-3: 候補シートを検査する
python tools/validate_sprite.py --spec <asset-spec.json> --motion <motion.json> --build-report work/<character-id>/reports/build.json --input work/<character-id>/<character-id>_candidate.png --report work/<character-id>/reports/validation.json

# B-6: 検査・目視・manifest記録の完了後に採用する
python tools/promote_sprite.py --spec <asset-spec.json> --motion <motion.json> --build-report work/<character-id>/reports/build.json --input work/<character-id>/<character-id>_candidate.png --target assets/characters/<character-id>_pixel_8dir.png
```

実行ログと `reports/validation.json` は候補シートと一緒に残す。`promote_sprite.py` は内部で再度validatorを実行するため、最後のコピーだけで未検証素材を採用することはできない。

## チェックリスト

### 制作前

- [ ] asset specに正規化条件、固定パレット、例外を記録した
- [ ] 40フレームのmotion specとPose Guideを準備した
- [ ] Character Master、Direction Reference、Style Referenceを固定した
- [ ] 同一条件の系列候補を比較する方法を決めた

### 採用前

- [ ] 40フレームが揃い、各フレームを共通の正規化経路で処理した
- [ ] 自動検査に合格し、検査レポートを保存した
- [ ] 通常・低速・ループ・シルエット表示で人間レビューした
- [ ] manifestに生成条件、参照素材の出所、レビュー結果を記録した
