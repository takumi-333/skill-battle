# 8方向スプライト素材作成フロー

本書は、[ガイドライン](8方向スプライト素材作成ガイドライン.md)で定めた完成条件を満たすための作業手順である。各コマンドの入出力と責務は[ツール一覧](ツール一覧.md)を正本とする。

## 作業の全体像

```text
事前準備 → RV-1: 制作設計レビュー
  ↓
フレーム単位: 生成・候補選定 → 背景除去 → 正規化・pixelization
  ↓
RV-2: キーフレームレビュー
  ↓
パターン単位: 残りのフレームを制作 → プレビュー再生 → RV-3: 動作レビュー
  ↓
シート単位: 組版 → 自動検査 → プレビュー再生 → RV-4: 最終レビュー → 履歴記録 → 採用
```

レビュー（RV）は、次の制作段階へ進むための人間による確認である。各RVの結果は、対象・確認観点・判定・差し戻し先を`work/<character-id>/reports/reviews/`に記録する。フレーム単位の作業と、40フレームが揃ってから行うシート単位の作業を混ぜない。これにより、不具合があったときに必要なフレームだけを修正できる。

## 0. 事前準備

1. キャラクター設定、既存素材、asset spec、motion specを確認する。
2. asset specにセル・シート構成、アンカー、正規化条件、固定パレット、例外を記録する。
3. motion specに40フレームのID、方向、位相、必要なroot・接地情報を記録する。
4. Character Master、Direction Reference、Style Reference、各フレームのPose Guideを用意する。
5. `work/<character-id>/` に、`reference/`、`raw/`、`rgba/`、`frames/`、`reports/`を用意する。

### RV-1: 制作設計レビュー

asset spec、motion spec、Pose Guideをすべて作成してから、人間レビューを行う。40フレームの制作は、このRVに承認されてから始める。

| 確認すること | 差し戻し先 |
| --- | --- |
| セル・シート構成、アンカー、正規化条件、パレット、例外がasset specにそろっている | asset spec |
| 40フレームのID・方向・位相とroot・接地情報がmotion specにそろっている | motion spec |
| Pose Guideが各フレームの意図、頭頂・root・接地足・武器位置を示している | Pose Guide |
| Character Master、Direction Reference、Style Referenceとの整合が取れている | 参照素材または各spec |

## A. フレーム単位で制作する

各 `frame ID` について、次の手順を繰り返す。パターンとは、motion specでひとまとまりとして確認するアニメーションの単位（例: 1方向の停止・歩行セット）を指す。

1. Character Master、該当方向のDirection Reference、Style Reference、該当Pose Guideを入力して高解像度候補を生成する。全フレームで同じCharacter Masterと生成設定を使い、ローカル生成では共通seed bank、クラウド生成では共通Master Referenceを継続する。背景・床・影・文字は要求しない。
2. 向き、ポーズ、服・髪・武器の特徴が参照に合う候補を残す。候補の採否は最終的に40フレームの系列として比較するため、この時点で余白、足元位置、画像全体の大きさは判定しない。
3. 選んだ候補を `raw/<frame-id>/` に残し、背景を除去して `rgba/<frame-id>.png` を作る。
4. alpha閾値後の前景bboxを使い、asset specの正規化条件で `frames/<frame-id>.png` へ正規化・pixelizationする。固定パレットへのexact remapとalphaの二値化もこの工程で行う。
5. `cleanup_frame_artifacts.py`で8近傍連結成分を調べ、キャラクター本体から設定距離を超える孤立成分や極小成分を除去する。除去した成分、距離、画素数はレポートへ記録する。大きく離れた成分は自動削除せず、レビュー待ちとして失敗させる。
6. cleanupで前景bboxが変わった場合は、cleanup済み画像を`pixelize_frame.py`へ再入力して目標高さ・固定パレット・二値alphaを再確定する。出力した64×64px画像を確認し、`--check-only`で再正規化後の残留ごみを再検査してからシート化へ進める。

個別フレームを手作業で `x=32, y=56` に置く必要はない。セル内のroot／足元を揃えるのは、シート組版時の責務である。

### RV-2: キーフレームレビュー

各パターンの最初のキーフレームをA-1からA-5まで処理した時点で、人間レビューを行う。残りのフレームを制作する前に、生成画像のイメージが正しいことを確定するためのRVである。

| 確認すること | 差し戻し先 |
| --- | --- |
| 顔、衣装、髪、武器、配色がキャラクター設定と参照に合う | A-1 |
| 向き、ポーズ、シルエット、画風が意図に合う | A-1 またはPose Guide |
| 64×64px化後にも読み取れる輪郭・重要な特徴になっている | A-4 |
| 背景、床、影、文字、不要な半透明が残っていない | A-3 またはA-4 |
| キャラクターから離れた孤立成分がなく、cleanupレポートが合格している | A-5 |

不承認の場合は、残りのフレームを作り始めない。参照・Pose Guide・生成条件のいずれを直すかを記録してから差し戻す。

### RV-3: パターンの動作レビュー

1パターン分のフレームがそろった時点で、[`preview_sprite_animation.py`](ツール一覧.md#preview_sprite_animationpy)で再生し、人間レビューを行う。ゲームを起動して確認することは、このRVの前提にしない。

通常速度・低速・ループで確認し、必要に応じて等倍・4倍nearest・シルエットも併用する。歩行の連続性、body bob、foot sliding、武器・手足の破綻、ループ端、各フレームのキャラクター同一性を確認する。不承認なら、問題のある`frame ID`を特定してA-1へ戻る。

## B. シート単位で検査・採用する

1. `frames/` にmotion specの全40 IDが存在することを確認する。
2. 候補シートを作成する。build reportに、各フレームのrootまたはfallback anchor、移動量、bbox、接地点を残す。
3. 候補シートを自動検査する。`validate_sprite.py`は各セルのartifact cleanup最終チェックも行う。失敗した場合はレポートの `frame ID` に戻り、該当フレームだけを修正して再作成する。
4. 自動検査に合格した候補を、`preview_sprite_animation.py`で再生する。8方向すべての停止・歩行をゲーム起動なしで切り替え、通常速度、0.25倍、ループ、等倍、4倍nearest、シルエットで確認できる状態にする。
5. RV-4として、完成した全アニメーションを人間レビューする。RV-2・RV-3で確認済みの内容に加え、方向間の一貫性、全パターンのループ、セル越境、採用候補全体の見え方を確認する。不承認なら、該当フレームまたはパターンへ差し戻す。
6. 生成器・モデル・プロンプト版・参照素材の出所・パレット・各RVの結果を `manifest.json` に記録する。
7. 自動検査とRV-1からRV-4のすべてに合格した候補だけを採用する。

## 差し戻しの判断

| 問題 | 戻る工程 |
| --- | --- |
| 透明背景、半透明ノイズ、不要な残留画素 | A-3 |
| 身体サイズ、横幅、パレット、alpha | A-4 |
| ポーズ、向き、顔・服・武器の不一致 | A-1 |
| root、接地、セル内の位置 | B-2の入力となるmotion specまたは個別フレーム |
| 歩行の連続性、同一性、ループ | 該当フレームのA-1 |
| asset spec、motion spec、Pose Guideの不足・矛盾 | 0. 事前準備（RV-1） |
| キーフレームの外見・画風が意図と異なる | RV-2からA-1 |
| パターンの動きが破綻している | RV-3から該当フレームのA-1 |
| 全体確認で方向間・パターン間の不整合が見つかった | RV-4から該当パターンまたはフレーム |

40フレームすべてを再生成するのは、Character MasterまたはStyle Referenceそのものが誤っていた場合だけとする。既存候補で足元が揃っている一方で人物だけが小さい場合は、再生成の前に元RGBA画像をasset specの正規化条件で再pixelizationする。

## 実行順の例

以下は `down_walk_01` を処理し、40フレームが揃った後にシート化する例である。

```text
# A-3: 選んだAI候補から背景を除去する
python tools/extract_alpha.py work/<character-id>/raw/down_walk_01/candidate_01.png work/<character-id>/rgba/down_walk_01.png

# A-4: 閾値後のbboxで64×64pxへ正規化・pixelizationする
python tools/pixelize_frame.py work/<character-id>/rgba/down_walk_01.png work/<character-id>/frames/down_walk_01.png --spec <asset-spec.json> --alpha-threshold 8 --content-height 56 --max-visible-width 60

# A-5: 離れた孤立成分を除去し、除去後に残留ごみがないことを確認する
python tools/cleanup_frame_artifacts.py work/<character-id>/frames/down_walk_01.png work/<character-id>/frames/down_walk_01.cleaned.png --spec <asset-spec.json> --report work/<character-id>/reports/down_walk_01.cleanup.json
python tools/pixelize_frame.py work/<character-id>/frames/down_walk_01.cleaned.png work/<character-id>/frames/down_walk_01.png --spec <asset-spec.json>
python tools/cleanup_frame_artifacts.py work/<character-id>/frames/down_walk_01.png work/<character-id>/frames/down_walk_01.final.png --spec <asset-spec.json> --report work/<character-id>/reports/down_walk_01.cleanup-final.json
python tools/cleanup_frame_artifacts.py work/<character-id>/frames/down_walk_01.final.png --spec <asset-spec.json> --check-only --report work/<character-id>/reports/down_walk_01.cleanup-check.json

# RV-3: 1パターンのフレームがそろったら、HTMLを開いて動きをレビューする
python tools/preview_sprite_animation.py --spec <asset-spec.json> --motion <motion.json> --frames-dir work/<character-id>/frames --output work/<character-id>/reports/reviews/pattern-review.html

# B-2: 全フレームが揃った後に候補シートを作る
python tools/build_sprite.py --spec <asset-spec.json> --motion <motion.json> --frames-dir work/<character-id>/frames --output work/<character-id>/<character-id>_candidate.png --report work/<character-id>/reports/build.json

# B-3: 候補シートを検査する
python tools/validate_sprite.py --spec <asset-spec.json> --motion <motion.json> --build-report work/<character-id>/reports/build.json --input work/<character-id>/<character-id>_candidate.png --report work/<character-id>/reports/validation.json

# RV-4: 完成候補の全アニメーションをHTMLでレビューする
python tools/preview_sprite_animation.py --spec <asset-spec.json> --motion <motion.json> --input work/<character-id>/<character-id>_candidate.png --output work/<character-id>/reports/reviews/final-review.html

# B-7: 検査・RV-1〜RV-4・manifest記録の完了後に採用する
python tools/promote_sprite.py --spec <asset-spec.json> --motion <motion.json> --build-report work/<character-id>/reports/build.json --input work/<character-id>/<character-id>_candidate.png --target assets/characters/<character-id>_pixel_8dir.png
```

`preview_sprite_animation.py`の入力と出力は[ツール一覧](ツール一覧.md#preview_sprite_animationpy)に従う。実行ログ、`reports/validation.json`、各RVの記録は候補シートと一緒に残す。`promote_sprite.py`は内部で再度validatorを実行するため、最後のコピーだけで未検証素材を採用することはできない。

## チェックリスト

### 制作前

- [ ] asset specに正規化条件、固定パレット、例外を記録した
- [ ] 40フレームのmotion specとPose Guideを準備した
- [ ] Character Master、Direction Reference、Style Referenceを固定した
- [ ] 同一条件の系列候補を比較する方法を決めた
- [ ] RV-1でasset spec、motion spec、Pose Guideの承認を得た

### 採用前

- [ ] 40フレームが揃い、各フレームを共通の正規化経路で処理した
- [ ] 各パターンのキーフレームをRV-2で承認した
- [ ] 各パターンをプレビュー再生し、RV-3で動きを承認した
- [ ] 自動検査に合格し、検査レポートを保存した
- [ ] 全アニメーションをゲーム起動なしでプレビュー再生し、RV-4で承認した
- [ ] manifestに生成条件、参照素材の出所、レビュー結果を記録した
