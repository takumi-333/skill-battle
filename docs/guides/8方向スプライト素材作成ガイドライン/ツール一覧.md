# スプライト制作ツール一覧

本書は、8方向スプライト制作で用いるツールのインターフェースと責務を定義する。

## 責務の境界

| ツール | 主な入力 | 主な出力 | 保証すること | 保証しないこと |
| --- | --- | --- | --- | --- |
| `extract_sheet_frames.py` | 既存シート、motion spec | 参照用フレーム群 | 既存シートを非破壊で分割する | キャラクターの品質評価 |
| `extract_alpha.py` | 生成候補画像 | RGBA PNG | 既存alphaの保持または単色背景の透過化 | 複雑な背景の高精度な切り抜き |
| `pixelize_frame.py` | RGBA、asset spec、任意のパレット | 64×64px個別フレーム | 正規化、pixelization、パレット、二値alpha | rootを基準にしたセル内配置 |
| `build_sprite.py` | 個別フレーム、asset spec、motion spec | 候補シート、build report | rootまたはfallback anchorによる位置合わせと組版 | 画像の拡縮、外見品質の修正 |
| `validate_sprite.py` | 候補シート、asset spec、任意のmotion spec・build report | validation report、終了コード | 形式・色・透明度・サイズ・配置の規格検査 | 歩行の自然さ、キャラクター同一性 |
| `promote_sprite.py` | 検査対象シート、asset spec、任意のmotion spec・build report | 採用先PNG、promotion validation report | 再検査に合格した候補だけの反映 | 人間レビュー、manifestの記録 |

## 共通入力

### asset spec

キャラクターごとの出力規格を表すJSONである。ツールはキャンバス、セルサイズ、足元アンカー、列・行順、正規化条件、固定パレットを参照する。値の定義と標準値はガイドラインを正本とする。

### motion spec

40フレームのID、方向、位相、任意のroot／接地情報を表すJSONである。フレームIDは、`raw`、`rgba`、`frames`の各成果物を対応付けるキーになる。

```text
id                    個別フレームのファイル名になるID
direction             asset specのcolumnsにある方向ID
phase                 asset specのrowsにある行ID
root / root_anchor    個別64pxフレーム上のroot座標（任意）
contact_foot          接地している足の識別子（任意）
contact_point         個別64pxフレーム上の接地点（任意）
ground_y              シート配置後に期待する接地点Y座標（任意）
```

## 個別ツール

### `extract_sheet_frames.py`

- 入力: `--sheet`（既存シート）、`--motion`、`--output-dir`
- 出力: `--output-dir/<frame-id>.png`、分割フレーム数と出力先のJSON
- 処理: motion specの方向・位相からセルを求め、64×64px単位で分割する。Character MasterやDirection Reference用に既存採用素材を利用するときに使う。

### `extract_alpha.py`

- 入力: `input`、`output`、必要に応じて`--threshold`または`--force-chroma-key`
- 出力: RGBA PNG、alphaの取得元・処理方法・背景色・しきい値のJSON
- 処理: 既存alphaを保持する。完全不透明な画像では四隅の平均RGBを背景色として推定し、色差がしきい値以内の画素を透明化する。既定のしきい値は18である。

### `pixelize_frame.py`

- 入力: `input`、`output`、`--spec`、必要に応じて`--palette`、正規化値の上書き引数
- 出力: 指定サイズのRGBA PNG、元bbox・可視サイズ・alpha／パレット処理結果のJSON
- 処理: alpha閾値後の前景bboxから縮尺を決め、LANCZOSで縮小し、固定パレットへexact remapしてalphaを二値化する。固定パレットがない場合だけ、最大色数による互換量子化へフォールバックする。

### `build_sprite.py`

- 入力: `--spec`、`--motion`、`--frames-dir`、`--output`、`--report`
- 出力: 8列×5行のRGBA候補シート、列・行・移動量・bbox・root／接地点を持つbuild report
- 処理: rootまたは`root_anchor`を`foot_anchor`へ移動する。rootがない場合だけ、alpha閾値後bboxのbottom-centerをfallback anchorに使う。拡縮は行わない。

### `validate_sprite.py`

- 入力: `--spec`、`--input`、`--report`、必要に応じて`--motion`、`--build-report`、各許容差
- 出力: `pass`または`fail`、エラー、警告、フレーム別計測値を持つvalidation report。終了コードは合格が`0`、不合格が`1`。
- 処理: RGBA、シート寸法、全セルの前景、二値alpha、固定パレット、身体高さ、横幅、占有率、停止／歩行比を検査する。motionとbuild reportがある場合はrootと接地点も検査する。

### `promote_sprite.py`

- 入力: `--spec`、`--input`、`--target`、必要に応じて`--motion`、`--build-report`
- 出力: 採用先PNG、`<input>.promotion-validation.json`相当の検査レポート、`promoted`または`refused`のJSON
- 処理: 内部で`validate_sprite.py`を再実行する。不合格ならコピーせず`refused`で終了し、合格した場合だけ採用先を作成または更新する。

## 人とツールの分担

| 判定・処理 | 担当 |
| --- | --- |
| 顔・衣装・武器・ポーズがキャラクターとして正しいか | 参照素材、候補選定、人間レビュー |
| 背景透過の初期処理 | `extract_alpha.py` |
| 身体の縮尺、固定パレット、二値alpha | `pixelize_frame.py` |
| rootを基準にしたセル内の位置 | `build_sprite.py` |
| 規格上の不合格判定 | `validate_sprite.py` |
| 検査済み候補だけを正式素材へ反映 | `promote_sprite.py` |

AI生成が成功してもvalidatorが不合格なら採用しない。逆にvalidatorが合格しても、人間レビューが済むまでは採用しない。
