# キャラクターアセット制作ガイド

## 目的

本ガイドは、追加キャラクターの立ち絵とゲーム用8方向アニメーションスプライトを、同じ品質・構成で再現可能に作るための制作手順を定める。

世界観・配色・質感の共通基準は [世界観・アートディレクション](../specs/世界観・アートディレクション.md)、キャラクターごとの外見設定は [キャラクター設定](../specs/キャラクター設定.md) を正とする。本書は、画像生成・検査・配置のノウハウを扱う。

## 前提
8方向スプライトは、ゲームの対戦時の停止・移動表示に用いる。40セルをゲーム上で高速に切り替えても、同じ人物が自然に歩いて見えることを重視する。

## 作成するアセット

キャラクターIDを `<id>` としたとき、次の2種類を作る。

| 種類 | ファイル名 | 用途 |
| --- | --- | --- |
| 立ち絵 | `assets/characters/<id>_idle.png` | キャラクター紹介、選択画面などに使う全身立ち絵 |
| 8方向スプライト | `assets/characters/<id>_pixel_8dir.png` | 対戦画面で使う停止・歩行アニメーション |

例: `typist_idle.png` と `typist_pixel_8dir.png`。

## 共通のデザイン契約

生成前に、世界観仕様とキャラクター設定から次を抜き出して「デザイン契約」として固定する。

- 性格の起点と、大罪モチーフをどう外見・所作へ翻訳するか
- 髪型・髪色・帽子など、小表示でも識別できる要素
- 武器、キャラクターシンボル、衣装の大きなシルエット
- メインカラー、アクセントカラー、暗色のベースカラー
- アクセサリー、護符、刺繍などの固定小物
- 年齢層、体格、雰囲気
- 禁止事項（固定要素にない武器・記号の追加、過度な露出、別キャラクターと混同する配色など）

立ち絵と全アニメーションシートで、同じデザイン契約を繰り返し記載する。立ち絵だけを参照に任せず、文字でも固定要素を指定する。

対象キャラクターのゲーム内スプライトがすでに存在する場合は、その画像を同一キャラクターの**ゲーム内トンマナ基準**として必ず確認する。新しいモーションは、既存スプライトと同じ頭身、セル内の占有率、ドット密度、輪郭の太さ、配色の明度帯を維持する。立ち絵の描き込み量や別の生成結果を基準に、ゲーム内で浮く別レンダリングへ置き換えてはならない。

## 立ち絵の制作

### 仕様

- 透過RGBA PNG
- 全身、1人だけ、右向きの3/4立ち姿
- 1254×1254pxを基準とする1:1の正方形キャンバス。1辺が1024px未満の画像は採用しない
- 背景、地面、影、文字、ロゴ、透かし、枠を含めない
- アニメ調のダークポップなゲーム向け立ち絵。ドット絵にはしない
- 暗いゴシック／ストリートの衣装をベースに、テーマカラーと金具・ルーン・ネオン光を限定的に使う
- 地下街やネオン看板などの世界観要素は人物の衣装や小物で表現し、背景として描かない

### プロンプトの骨子

```text
Asset type: full-body character idle portrait for a dark-pop arcade fantasy fighting game
Primary request: <デザイン契約を含む人物説明>
Scene/backdrop: genuinely transparent RGBA background, no floor, no cast shadow
Style/medium: polished anime-inspired character illustration; dark midnight arcade, gothic streetwear,
subtle neon accents and metal details expressed only through the character design
Composition/framing: one character only, full body, right-facing three-quarter standing pose, centered in a square frame
Constraints: include only the weapon and symbols specified by the design contract; no text, logo, watermark, scenery, other character
Avoid: <禁止事項>
```

生成後は、全身が収まること、透過背景であること、固定要素が揃うことを確認する。

## 8方向アニメーションスプライトの制作

### 共通ファイル仕様

移動スプライトは、次の形式とする。

- 透過RGBA PNG、512×320px
- 64×64pxセルを8列×5行に配置し、合計40フレーム
- 列順: 下 / 下左 / 左 / 上左 / 上 / 上右 / 右 / 下右
- 行順: 停止 / 歩行1 / 歩行2 / 歩行3 / 歩行4
- 歩行は接地 / 中間 / 逆接地 / 中間の4フレームループとする。
- 斜め上見下ろし（3/4トップダウン）。頭頂・肩・足元が見える
- 左右反転に依存せず、8方向を個別に描く
- 背景、床、影、発光、罫線、文字、ラベル、透かしを含めない

### 生成時の重要事項

AI画像生成では、最終解像度でなく大きなシートが出力される場合がある。最終的には各セルを64×64pxへ最近傍補間で正規化する。

次の条件をプロンプトへ入れる。

- **正確に8列×5行、40フレーム**
- **各セルの周囲に十分な透明余白を置く**
- **ケープ、髪、袖、装飾を隣のセルへはみ出させない**
- **すべてのフレームを単一の接続したシルエットにし、孤立した切れ端・粒子を作らない**
- 背景色、床、影、発光、罫線、文字を入れない

### プロンプトの骨子

```text
Asset type: production 2D pixel-art animation sprite sheet for a top-down dark-pop arcade fantasy action game
Primary request: <デザイン契約を含む人物説明>
Style/medium: true handcrafted 16-bit pixel art, crisp hard-edged pixels, limited palette,
no antialiasing, no painterly or vector rendering; dark clothing with readable character-color accents
Camera/view: 3/4 top-down action-RPG view; top of head, shoulders and feet visible
Composition/framing: EXACTLY 8 columns by 5 rows; one isolated full-body sprite per cell;
generous completely transparent gutter on every side; no sprite pixel crosses a cell boundary.
Columns: down, down-left, left, up-left, up, up-right, right, down-right.
Row 1: idle. Rows 2-5: contact, passing, opposite contact, passing.
Scene/backdrop: genuinely transparent RGBA background only
Constraints: same person and fixed design in all 40 frames; directions drawn individually; no detached fragments or stray pixels.
Avoid: background, floor, shadow, glow, text, grid, labels, watermark, border, <禁止事項>
```

## 正規化と透過処理

1. 生成元の背景がすでに透過（角のアルファ値が0）なら、背景除去を行わない。
2. 生成元を8列×5行に等分する。
3. 各元セルを縦横比を保ったまま64×64pxへ最近傍補間で縮小する。
4. 各フレームの足元を64pxセルの下端へ揃える。
5. 512×320pxのRGBA PNGとして保存する。

背景除去を誤って黒髪や濃色衣装へ適用すると、輪郭が透明化され、ゲーム中に切れ端がちらつく。生成元が透過なら、この処理は絶対に行わない。

セル外へはみ出した装飾や孤立した切れ端が見つかった場合、切り貼りで直すより、透明余白を明示してスプライトシートを再生成する。

## 検査チェックリスト

- [ ] 立ち絵を依頼した場合は `<id>_idle.png` が存在する
- [ ] スプライトが `<id>_pixel_8dir.png` として存在する
- [ ] スプライトが512×320px、RGBA、40セルである
- [ ] 40セルすべてにキャラクター画素がある
- [ ] 8方向で髪・衣装・武器・小物・足元の向きを区別できる
- [ ] 停止行と歩行4フレーム行の順序が正しい
- [ ] スプライト間に切れ端、隣接セルの混入、欠けがない
- [ ] 立ち絵とスプライトでデザイン契約が一致している
- [ ] 対戦画面で本来の画像色が保持され、プレイヤー色でモジュレートされない

## Godotへの反映

- 新しい8方向シートは表示用IDから選ぶ。能力・課題の内部IDには結び付けない。
- `facing` を45度単位に丸め、列順に対応する64×64pxセルを描画する。
- 停止時は行0、移動時は行1〜4を8fpsで循環する。
- スプライトの色は `Color.WHITE` で描画し、P1/P2のチームカラーを画像へ乗算しない。
