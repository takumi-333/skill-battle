# キャラクターアセット制作ガイド

## 目的

本ガイドは、追加キャラクターの立ち絵とゲーム用8方向アニメーションスプライトを、同じ品質・構成で再現可能に作るための制作手順を定める。

世界観・配色・質感の共通基準は [世界観・アートディレクション](../specs/世界観・アートディレクション.md)、キャラクターごとの外見設定は [キャラクター設定](../specs/キャラクター設定.md) を正とする。本書は、画像生成・検査・配置のノウハウを扱う。

## 前提
8方向アニメーションスプライトは、ゲームの対戦時のアニメーションに用いる。
8方向への移動、8方向への攻撃、8方向でチャージしている様子が見れるようにしたい
そのためそれらのスプライトに、素材の少しのずれとかも違和感として表れてしまうため、**64枚をゲーム上で高速に切り替えても、同じ人物が同じ場所で連続運動しているように見えるか**が重要となる。

## 作成するアセット

キャラクターIDを `<id>` としたとき、次の4種類を作る。

| 種類 | ファイル名 | 用途 |
| --- | --- | --- |
| 立ち絵 | `assets/characters/<id>_idle.png` | キャラクター紹介、選択画面などに使う全身立ち絵 |
| 移動 | `assets/characters/<id>_move_8dir.png` | 対戦画面で使う8方向・8フレームの移動ループ |
| 攻撃 | `assets/characters/<id>_attack_8dir.png` | 対戦画面で使う8方向・8フレームの一回再生攻撃モーション |
| 集中 | `assets/characters/<id>_focus_8dir.png` | スキル発動中に使う8方向・8フレームの集中状態ループ |

例: `typist_idle.png`、`typist_move_8dir.png`、`typist_attack_8dir.png`、`typist_focus_8dir.png`。

## 共通のデザイン契約

生成前に、世界観仕様とキャラクター設定から次を抜き出して「デザイン契約」として固定する。

- 性格の起点と、大罪モチーフをどう外見・所作へ翻訳するか
- 髪型・髪色・帽子など、小表示でも識別できる要素
- 武器、キャラクターシンボル、衣装の大きなシルエット
- メインカラー、アクセントカラー、暗色のベースカラー
- アクセサリー、護符、刺繍などの固定小物
- 年齢層、体格、雰囲気
- 禁止事項（固定要素にない武器・記号の追加、過度な露出、別キャラクターと混同する配色など）

立ち絵と全アニメーションシートで、同じデザイン契約を繰り返し記載する。立ち絵だけを参照に任せず、文字でも固定要素を指定する。

対象キャラクターのゲーム内スプライトがすでに存在する場合は、その画像を同一キャラクターの**ゲーム内トンマナ基準**として必ず確認する。新しいモーションは、既存スプライトと同じ頭身、セル内の占有率、ドット密度、輪郭の太さ、配色の明度帯を維持する。立ち絵の描き込み量や別の生成結果を基準に、ゲーム内で浮く別レンダリングへ置き換えてはならない。

## 立ち絵の制作

### 仕様

- 透過RGBA PNG
- 全身、1人だけ、右向きの3/4立ち姿
- 1254×1254pxを基準とする1:1の正方形キャンバス。1辺が1024px未満の画像は採用しない
- 背景、地面、影、文字、ロゴ、透かし、枠を含めない
- アニメ調のダークポップなゲーム向け立ち絵。ドット絵にはしない
- 暗いゴシック／ストリートの衣装をベースに、テーマカラーと金具・ルーン・ネオン光を限定的に使う
- 地下街やネオン看板などの世界観要素は人物の衣装や小物で表現し、背景として描かない

### プロンプトの骨子

```text
Asset type: full-body character idle portrait for a dark-pop arcade fantasy fighting game
Primary request: <デザイン契約を含む人物説明>
Scene/backdrop: genuinely transparent RGBA background, no floor, no cast shadow
Style/medium: polished anime-inspired character illustration; dark midnight arcade, gothic streetwear,
subtle neon accents and metal details expressed only through the character design
Composition/framing: one character only, full body, right-facing three-quarter standing pose, centered in a square frame
Constraints: include only the weapon and symbols specified by the design contract; no text, logo, watermark, scenery, other character
Avoid: <禁止事項>
```

生成後は、全身が収まること、透過背景であること、固定要素が揃うことを確認する。

## 8方向アニメーションスプライトの制作

### 共通ファイル仕様

移動・攻撃・集中の各シートは、すべて次の形式とする。

- 透過RGBA PNG、512×512px
- 64×64pxセルを8列×8行に配置し、合計64フレーム
- 列順: 下 / 下左 / 左 / 上左 / 上 / 上右 / 右 / 下右
- 行順: フレーム1からフレーム8。上から下へ時間が進む
- **列が方向、行が時間**である。この配置は一般的な「行が方向、列が時間」の並びと異なる場合があるため、後工程で転置してはならない。
- 斜め上見下ろし（3/4トップダウン）。頭頂・肩・足元が見える
- 左右反転に依存せず、8方向を個別に描く
- 武器、帽子、長い髪、ローブの裾などの大きな識別要素は、各セル内に収めたまま全方向で維持する
- 背景、床、影、罫線、文字、ラベル、透かしを含めない。移動・攻撃には常時発光や粒子を含めない。
- 集中に限り、テーマカラーの光が外周からキャラクター／武器へ集まり、身体に沿うオーラが高まる演出を含めてよい。光はフレーム順に収束と小さな強弱を繰り返す持続的なエフェクトとし、周期ごとに消失・解放してゼロへ戻してはならない。無関係な切れ端やランダムな粒子に見せない。

### 共通アンカー・スケール・身体軸（P0）

スプライトのゲーム上の座標を安定させるため、各64×64pxセルでは次の契約をすべての方向・モーション・フレームに適用する。

- 共通アンカー（root）はセル内座標 **`[32, 44]`** とする。これはゲーム上のキャラクター座標に対応する地面接地点であり、全フレームで固定する。
- 歩行中に接地する足や、武器の先端をアンカーとしてはならない。歩行による上下動は身体内部のポーズ変化として表現し、スプライト全体の配置をずらして表現しない。
- 移動・攻撃・集中の切替時にもrootを同一位置に保つ。特に move → attack、attack終了 → move（ゲーム用idleを追加する場合はidleも含む）、move → focus、focus → attack で、人物が数pxワープして見えてはならない。なお、本ガイドの立ち絵はゲーム用idleスプライトではない。
- キャラクタースケールは全シートで固定する。フレーム単位で人物のタイトなバウンディングボックスを64pxへ最大化してはならない。武器・髪・衣装の動きによる占有範囲の変化は許容するが、人物本体を拡大・縮小しない。
- 通常立ち姿勢の頭頂からrootまでの標準高さは **40〜44px** とする。同じ方向の各フレームでは、姿勢変化による自然な差を除き、この寸法を原則 **±1px以内** に保つ。
- 同一方向の8フレームでは、キャラクター全体の基本facing角度と奥行き関係を固定する。肩・腰・頭部の捻りは許容するが、フレームごとに全身の向きが変化してはならない。
- 各方向で、前に出る肩、武器を持つ手、前足・後足、背中側に隠れる装飾を固定する。斜め方向でも、これらの前後関係を8フレーム一貫して維持する。

### モーション別の要件

| モーション | 再生 | 8フレームの内容 |
| --- | --- | --- |
| 移動 | 循環、12fpsを基準 | 下記の固定した歩容サイクルに従う。フレーム8からフレーム1へ自然につなげ、上半身、髪、武器、衣装も足運びに追従させる。 |
| 攻撃 | 一回再生、12fpsを基準 | キャラクターごとの「攻撃モーション契約」に従う。共通の時間配分は1～2: 予備動作、3～5: 主動作、6: 最大到達点、7～8: 戻りとする。攻撃判定・エフェクトは実装側で合わせるため、スプライト内のroot motionは禁止する。 |
| 集中（Focus） | 循環、10fpsを基準 | スキル課題の実行中に継続表示する集中状態。キャラクター本体は構え・呼吸・髪や布の小さな揺れに留め、テーマカラーの光を外側から手元・武器・身体へ集める。エフェクトは消失してゼロへ戻らず、強弱の小さい脈動として自然に循環させる。 |

#### 移動の歩容契約

左右はキャラクター本人の左・右とし、全方向で次の8フレームを同じ位相で用いる。向きによって前後の見え方が変わっても、接地・通過の順序を変えてはならない。

| フレーム | ポーズ |
| --- | --- |
| F1 | 左足のcontact pose（接地）、右足は後方 |
| F2 | 左足へ荷重 |
| F3 | 右足のpassing pose（左足を通過） |
| F4 | 右足が前方へ振り出される |
| F5 | 右足のcontact pose（接地）、左足は後方 |
| F6 | 右足へ荷重 |
| F7 | 左足のpassing pose（右足を通過） |
| F8 | 左足が前方へ振り出され、F1の左足接地へ連続する |

#### 攻撃モーション契約

デザイン契約とは別に、攻撃シートを作る前にキャラクターごとの契約を作成し、プロンプトとレビューへそのまま渡す。攻撃種別をキャラクター設定だけから推測させない。

```text
Attack Motion Contract

Attack type: <横薙ぎ / 縦振り / 突き / 射撃 / 杖振り / 詠唱 など>
Weapon hand: <left / right / both / none>
Startup stance: <F1時点の武器・身体の位置>
Attack direction: <facing方向との関係>
Main arc or path: <武器の柄・先端が通る空間的な軌道>
Peak frame: F6
Peak pose: <最大到達点の荷重・武器・身体の姿勢>
Recovery: <F7〜F8で戻る位置>
Root motion: none
Character translation: prohibited
VFX: none（ゲーム側で追加する場合はその旨を明記）
```

ゲームロジックがキャラクター位置を管理するため、スプライト内の前進・後退によるroot motionは禁止する。将来、root motionを用いる攻撃を実装する場合は、ゲーム仕様・移動処理・この契約を同時に変更する。

#### Focusの用途

本ガイドの `focus` は、ボタン長押しでエネルギーを貯めて解放するChargeではなく、課題を解いている間に継続するFocus状態を表す。したがって `focus_8dir.png` は持続時間にかかわらず破綻しないループとする。将来、開始演出や蓄積完了状態が必要になった場合は、既存のループに混在させず `focus_start` と `focus_charged_loop` などを別仕様・別シートとして定義する。

止まっているように見えるフレームの複製で埋めない。移動では歩容契約に沿う重心と足運び、攻撃ではモーション契約に沿う溜めと武器軌道、集中では呼吸と布・髪・武器の微小な揺れを連続させ、滑らかさを作る。

### 生成時の重要事項

AI画像生成では、最終解像度でなく大きなシートが出力される場合がある。最終的には、シート全体を等倍のセル構成を保って64×64pxセルへ最近傍補間で正規化する。フレームごとにタイトなバウンディングボックスを取り、個別に64pxへ拡大・縮小してはならない。

次の条件を必ずプロンプトへ入れる。

- **正確に8列×8行、64フレーム**
- **各セルの周囲に十分な透明余白を置く**
- **ケープ、髪、袖、装飾を隣のセルへはみ出させない**
- 移動・攻撃は、すべてのフレームを単一の接続したシルエットにし、孤立した切れ端・粒子を作らない
- 集中の光は、収束方向とフレーム間の増減が明確な意図的エフェクトに限り、キャラクター本体から分離してよい。無関係な切れ端・ランダムな粒子は作らない
- **モーション種別に応じた連続した8フレームを描く。停止画の複製で埋めない**
- **各セルのrootを `[32, 44]` に固定し、通常立ち姿勢の頭頂からrootまでを40〜44pxに保つ。フレーム単位の拡大・縮小をしない**
- **同じ方向の8フレームではfacing角度、肩・手・足・背面装飾の前後関係を固定する**
- 移動は歩容契約のF1〜F8の位相を守る。攻撃はキャラクターごとの攻撃モーション契約を、説明の省略なく含める
- 背景色、床、影、グロー、罫線、文字を入れない

### プロンプトの骨子

```text
Asset type: production 2D pixel-art animation sprite sheet for a top-down dark-pop arcade fantasy action game
Primary request: <デザイン契約を含む人物説明。加えて、移動 / 攻撃 / 集中のいずれかのモーション指定>
Style/medium: true handcrafted 16-bit pixel art, crisp hard-edged pixels, limited palette,
no antialiasing, no painterly or vector rendering; dark clothing with readable character-color accents
Camera/view: 3/4 top-down action-RPG view; top of head, shoulders and feet visible
Composition/framing: EXACTLY 8 columns by 8 rows; one isolated full-body sprite per cell;
generous completely transparent gutter on every side; no sprite pixel crosses a cell boundary.
Columns: down, down-left, left, up-left, up, up-right, right, down-right.
Rows: animation frames 1 through 8, top to bottom.
Motion: <移動は歩容契約のF1〜F8に従う循環 / 攻撃は攻撃モーション契約に従う予備動作から戻りまでの一回再生 / 集中は小さな呼吸と構え、テーマカラーの光が外周から集まる持続Focus状態の循環>
Scene/backdrop: genuinely transparent RGBA background only
Constraints: same person and fixed design in all 64 frames; directions drawn individually;
keep the specified weapon, silhouette, and character symbols in every direction; no detached fragments or stray pixels.
Anchor and scale: in every 64x64 cell, fix the game root at [32, 44]; keep the normal standing head-to-root height 40-44px;
never individually scale frames to their bounding boxes. Keep the same facing angle and the same front/back relationship of shoulders, weapon hand, feet, and back-side accessories across the 8 frames of each direction.
Avoid: background, floor, shadow, text, grid, labels, watermark, border, <禁止事項>. For move and attack also avoid glow and particles; for focus allow only deliberate theme-colored inward-gathering energy and aura.
```

### 生成戦略とフォールバック

通常は8方向×8フレームの一括生成を用いる。ただし、独立品質レビューで人物・方向・時系列の一貫性が `FAIL` になった場合、同じ方法で無目的に再生成を繰り返さず、次の順で生成単位を変更する。

1. **通常**: 8方向×8フレームの一括生成。
2. **第1フォールバック**: 1方向×8フレーム（1列×8行）のstripを方向ごとに生成し、共通アンカー・共通スケールで8本を結合する。
3. **第2フォールバック**: 各方向のkey pose（移動はF1/F3/F5/F7、攻撃はF1/F2/F6/F8、集中はF1/F5）を先に固定し、その参照を用いて中間フレームを生成・補間する。

どの方式でも、デザイン契約、歩容契約または攻撃モーション契約、root、スケール、列順・行順を変えてはならない。結合後は必ず全シートを再レビューする。

## 正規化と透過処理

1. 生成元の背景がすでに透過（角のアルファ値が0）なら、背景除去を行わない。
2. 生成元を8列×8行に等分する。
3. **スケール正規化**: 全フレームの人物本体が基準寸法へ収まる共通の縮尺率を一つ決め、シート全体または全フレームへ同じ倍率の最近傍補間を適用する。フレームごとのタイトなバウンディングボックスに合わせた個別リサイズは禁止する。
4. **アンカー正規化**: 各フレームを64×64pxセルへ合成し、rootをセル内 `[32, 44]` に合わせる。接地している足の下端を揃えるのではなく、身体の共通アンカーを固定する。集中モーションを含め、ポーズによる揺れをスプライト全体の移動で補正しない。
5. 通常立ち姿勢の頭頂からrootまでが40〜44pxであり、同一方向内で原則±1px以内であることを確認する。
6. 512×512pxのRGBA PNGとして、モーション別のファイル名で保存する。

背景除去を誤って黒髪や濃色衣装へ適用すると、輪郭が透明化され、ゲーム中に切れ端がちらつく。生成元が透過なら、この処理は絶対に行わない。

セル外へはみ出した装飾や孤立した切れ端が見つかった場合、切り貼りで直すより、透明余白を明示してスプライトシートを再生成する。

## 独立品質レビュー

生成・正規化を担当していないサブエージェントが、正規化後の立ち絵と全3シートを直接見て品質を判定する。
レビュー担当には、対象ID、デザイン契約、モーション種別、列順・行順・期待寸法を渡す。
各シートは8×8のセル境界と個別セルを拡大して確認する。
レビュー担当は画像を編集せず、各項目を `PASS` / `FAIL` と具体的な根拠で報告する。

- 立ち絵の場合は、縦横比が正方形であり、全身・武器・主要装飾が欠けずに収まっている
- スプライトが512×512pxの8列×8行であり、各セルの人物が境界をまたいでいない
- 透明背景が正しく、髪・衣装・武器・輪郭が意図せず透明化・欠損していない
- 背景片、他キャラクターの部位、無関係な孤立画素群などの異物が混入していない。集中のテーマカラーによる収束光・オーラは、方向性とフレーム間の変化が明確なら許容する
- 8方向・8フレームが揃い、全シートで同一人物・同一デザイン契約を保っている
- 全セルのrootが `[32, 44]` に固定されており、モーション切替で人物全体がワープしない。通常立ち姿勢の頭頂からrootまでが40〜44pxで、同一方向では原則±1px以内である
- 同一方向の8フレームで、全身のfacing角度、前に出る肩、武器を持つ手、前足・後足、背面装飾の前後関係が一貫している
- 同一フレーム番号を8方向で横断比較し、頭身、頭部・肩幅、武器サイズ、キャラクター中心位置が一貫している。少なくともMoveのF1・F5、AttackのF1・F6、FocusのF1・F5を比較する

さらに、モーション別に次を判定する。

| モーション | `PASS` の判定基準 |
| --- | --- |
| 移動 | rootが固定され、頭部が不自然に跳ねない。歩容契約どおりF1/F5が左右反対のcontact pose、F3/F7がpassing poseである。手足・武器がフレーム間で反転または反対側へ瞬間移動せず、F8→F1も他の隣接フレームと同程度に連続し、人物本体の大きさが変化しない。 |
| 攻撃 | 攻撃モーション契約に従い、フレーム1→2で予備動作が強まり、2→3で攻撃方向へ加速する。最大伸長が明確で、到達後に逆向きへワープしない。武器の手・柄・先端をフレーム間で追跡しても接続と空間的な軌道が連続する。root motionの有無が契約どおりであり（現行契約ではなし）、フレーム8はフレーム1付近のニュートラルな姿勢へ戻る。 |
| 集中 | rootが固定され、呼吸による身体の上下動が小さい。エネルギーがランダムに出現・消失せず、外側→内側の流れを維持する。フレーム8→1でエフェクト量の差が過大でなく、自然に循環する。 |

レビュー結果は、作業報告にファイルごと・項目ごとに `PASS` / `FAIL` を記録する。`FAIL` には該当セルを `[列, 行]`（左上を `[1, 1]`）で示し、原因と「修正」または「再生成」の判断を添える。

一項目でも `FAIL` なら最終素材として確定しない。人物本体に影響しない単一の孤立画素の除去、透明余白の追加、正しい元画像の最近傍リサイズだけは修正してよい。欠け、透明化の誤り、異物、構図・比率の誤り、セル混入、フレーム不足、主要部分に接続する不要片は再生成を優先する。再生成時は「生成戦略とフォールバック」に従って方式を変更し、修正または再生成後は必ず再レビューする。第2フォールバック後も合格しない場合は、問題のある素材を完成品として配置せず、残る不合格理由をユーザーへ報告する。

## Godotへの反映

- 新しいシートは表示用IDから選ぶ。能力・課題の内部IDには結び付けない。
- `facing` を45度単位に丸め、列順に対応する64×64pxセルを描画する。
- 移動は行0～7を12fpsで循環、攻撃は行0～7を12fpsで一回再生、集中は行0～7を10fpsで循環する。
- 攻撃の当たり判定とスキルの光・粒子は、スプライトとは別のゲームロジック／エフェクトとして扱う。
- スプライトの色は `Color.WHITE` で描画し、P1/P2のチームカラーを画像へ乗算しない。
