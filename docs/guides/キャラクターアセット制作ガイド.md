# キャラクターアセット制作ガイド

## 目的

本ガイドは、追加キャラクターの立ち絵とゲーム用8方向アニメーションスプライトを、同じ品質・構成で再現可能に作るための制作手順を定める。

世界観・配色・質感の共通基準は [世界観・アートディレクション](../specs/世界観・アートディレクション.md)、キャラクターごとの外見設定は [キャラクター設定](../specs/キャラクター設定.md) を正とする。本書は、画像生成・検査・配置のノウハウを扱う。

## 前提
8方向スプライトは、ゲームの対戦時の停止・移動表示に用いる。40セルをゲーム上で高速に切り替えても、同じ人物が自然に歩いて見えることを重視する。

## 作成するアセット

キャラクターIDを `<id>` としたとき、次の2種類を作る。

| 種類 | ファイル名 | 用途 |
| --- | --- | --- |
| 立ち絵 | `assets/characters/<id>_idle.png` | キャラクター紹介、選択画面などに使う全身立ち絵 |
| 8方向スプライト | `assets/characters/<id>_pixel_8dir.png` | 対戦画面で使う停止・歩行アニメーション |

例: `typist_idle.png` と `typist_pixel_8dir.png`。

## 共通のデザイン契約

生成前に、世界観仕様とキャラクター設定から次を抜き出して「デザイン契約」として固定する。

- 性格の起点と、大罪モチーフをどう外見・所作へ翻訳するか
- 髪型・髪色・帽子など、小表示でも識別できる要素
- 武器、キャラクターシンボル、衣装の大きなシルエット
- メインカラー、アクセントカラー、暗色のベースカラー
- アクセサリー、護符、刺繍などの固定小物
- 年齢層、体格、雰囲気
- 禁止事項（固定要素にない武器・記号の追加、過度な露出、別キャラクターと混同する配色など）

立ち絵と全アニメーションシートで、同じデザイン契約を繰り返し記載する。立ち絵だけを参照に任せず、文字でも固定要素を指定する。

対象キャラクターのゲーム内スプライトがすでに存在する場合は、その画像を同一キャラクターの**ゲーム内トンマナ基準**として必ず確認する。新しいモーションは、既存スプライトと同じ頭身、セル内の占有率、ドット密度、輪郭の太さ、配色の明度帯を維持する。立ち絵の描き込み量や別の生成結果を基準に、ゲーム内で浮く別レンダリングへ置き換えてはならない。

## 立ち絵の制作

### 仕様

- 透過RGBA PNG
- 全身、1人だけ、右向きの3/4立ち姿
- 1254×1254pxを基準とする1:1の正方形キャンバス。1辺が1024px未満の画像は採用しない
- 背景、地面、影、文字、ロゴ、透かし、枠を含めない
- アニメ調のダークポップなゲーム向け立ち絵。ドット絵にはしない
- 暗いゴシック／ストリートの衣装をベースに、テーマカラーと金具・ルーン・ネオン光を限定的に使う
- 地下街やネオン看板などの世界観要素は人物の衣装や小物で表現し、背景として描かない

### プロンプトの骨子

```text
Asset type: full-body character idle portrait for a dark-pop arcade fantasy fighting game
Primary request: <デザイン契約を含む人物説明>
Scene/backdrop: genuinely transparent RGBA background, no floor, no cast shadow
Style/medium: polished anime-inspired character illustration; dark midnight arcade, gothic streetwear,
subtle neon accents and metal details expressed only through the character design
Composition/framing: one character only, full body, right-facing three-quarter standing pose, centered in a square frame
Constraints: include only the weapon and symbols specified by the design contract; no text, logo, watermark, scenery, other character
Avoid: <禁止事項>
```

生成後は、全身が収まること、透過背景であること、固定要素が揃うことを確認する。

## 8方向アニメーションスプライトの制作

### 共通ファイル仕様

移動スプライトは、次の形式とする。

- 透過RGBA PNG、512×320px
- 64×64pxセルを8列×5行に配置し、合計40フレーム
- 列順: 下 / 下左 / 左 / 上左 / 上 / 上右 / 右 / 下右
- 行順: 停止 / 歩行1 / 歩行2 / 歩行3 / 歩行4
- 歩行は接地 / 中間 / 逆接地 / 中間の4フレームループとする。
- 斜め上見下ろし（3/4トップダウン）。頭頂・肩・足元が見える
- 左右反転に依存せず、8方向を個別に描く
- 背景、床、影、発光、罫線、文字、ラベル、透かしを含めない

### 生成時の重要事項

AIには**完成スプライトシートを生成させない**。出力単位は1フレームであり、40フレーム分のmotion spec、Character Master、Direction Reference、Style Referenceを共通の生成コンテキストとして与える。Sprite Sheetは、採用済みの個別フレームをプログラムで組版した最終出力形式である。

生成前に、`assets/motions/humanoid_walk_8dir.json`などのmotion specで、全40フレームの方向、歩行位相、左右の足、body bob、足元アンカー、Pose Guideを固定する。AIには「歩行2枚目」を解釈させず、指定したPose Guideを指定キャラクターとして1枚だけレンダリングさせる。

各フレームの主参照は、すべて同じ不変のCharacter Master、Direction Reference、Style Reference、Pose Guideとする。直前フレームを次フレームの主参照にする連鎖は禁止する。隣接フレームは、微細な連続性を補助する二次参照に限る。

### 1フレーム用プロンプトの骨子

```text
Asset type: one production 2D game-character animation frame, not a sprite sheet
Primary request: <デザイン契約>を保った、<frame ID>の指定Pose Guideを取るキャラクター
Input images: Character Master, Direction Reference, Style Reference, Pose Guide
Style/medium: existing game spriteに合わせた、読みやすいピクセルアートのキャラクター素材
Camera/view: 3/4 top-down action-RPG view; top of head, shoulders and feet visible
Composition/framing: one full-body character only, centered, feet near the specified ground anchor
Scene/backdrop: genuinely transparent background
Constraints: 同じ人物、固定の髪・深緑の上着・黒いパンツ・金のキーキャップ付き大型ハンマーを維持する。背景、床、影、発光、文字、ロゴ、孤立した粒子を含めない。
Avoid: sprite sheet, grid, cells, labels, watermark, border, <禁止事項>
```

## 正規化と透過処理

1. source imageのalphaを確認する。ネイティブ透過なら保持し、不透明なら背景除去の方法・閾値・ツール版をmanifestへ記録する。
2. 高解像度のsemantic renderは、alpha閾値を適用した可視前景bboxを取得してから、pixelization、palette quantization、必要最小限のpixel cleanupを通して論理pixel gridを確定する。半透明の背景・縁ノイズをbboxへ含めてキャラクターを縮小してはならない。高解像度画像を`NEAREST`だけで64×64pxへ間引いてはならない。
3. asset specの`normalization`に、alpha bbox閾値、可視前景の目標高さ・許容差、最大可視幅、占有率範囲を定義する。目標高さは既存の採用素材から計測し、停止・歩行の全フレームを同じ契約で正規化する。
4. pixel grid確定後、各フレームを`cleanup_frame_artifacts.py`へ通し、8近傍連結成分でキャラクターから離れた孤立画素・ごみを除去する。除去内容をJSONへ記録し、`--check-only`で残留成分がないことを確認する。大きな遠隔成分は自動削除せずレビューへ戻す。
5. cleanup済みフレームから中心Xと足元を取得し、motion specのアンカーへ配置する。`NEAREST`はこの確定済みgridの拡大・縮小を壊さないためだけに使う。
6. 40枚の採用済みRGBAフレームを指定の方向・行・列へ機械的に組版し、512×320pxのRGBA PNGとして保存する。
6. 寸法・RGBA・40セル・透明背景・アンカー・可視高さ・占有率・パレットを検査し、通過した候補だけをGodot用ファイルに昇格する。

背景除去を誤って黒髪や濃色衣装へ適用すると、輪郭が透明化され、ゲーム中に切れ端がちらつく。ネイティブ透過を検出した素材には背景除去を適用しない。

### 制作ツールの前提

このパイプラインはPython 3.10以上とPillowを使う。初回だけ、利用するPython環境で次を実行する。

```text
python -m pip install Pillow
```

個別フレームの参照展開、透過処理、pixelization、artifact cleanup、組版、検査は`tools/extract_sheet_frames.py`、`extract_alpha.py`、`pixelize_frame.py`、`cleanup_frame_artifacts.py`、`build_sprite.py`、`validate_sprite.py`で行う。生成候補の保存先は`assets/generated/raw/`、検査済み候補の保存先は`assets/generated/validated/`とし、`assets/characters/`へは`promote_sprite.py`の検査成功後だけ配置する。

`assets/generated/`、`assets/manifests/`、`assets/motions/`、`assets/specs/` は生成パイプラインのローカル作業領域であり、`.gitignore` と `.gdignore` の対象である。raw画像、RGBA化画像、個別フレーム、候補シート、build／validationレポート、manifest、motion spec、asset specはコミットせず、Godotにもリソースとして読み込ませない。採用素材だけを`assets/characters/`へ昇格する。正式に残す仕様は`docs/specs/`へ、生成ツールは`tools/`へ配置する。新しいアセットでも同じディレクトリ規約を使う。

## 検査チェックリスト

- [ ] 立ち絵を依頼した場合は `<id>_idle.png` が存在する
- [ ] スプライトが `<id>_pixel_8dir.png` として存在する
- [ ] スプライトが512×320px、RGBA、40セルである
- [ ] 40セルすべてにキャラクター画素がある
- [ ] 8方向で髪・衣装・武器・小物・足元の向きを区別できる
- [ ] 停止行と歩行4フレーム行の順序が正しい
- [ ] スプライト間に切れ端、隣接セルの混入、欠けがない
- [ ] 立ち絵とスプライトでデザイン契約が一致している
- [ ] 対戦画面で本来の画像色が保持され、プレイヤー色でモジュレートされない

## Godotへの反映

- 新しい8方向シートは表示用IDから選ぶ。能力・課題の内部IDには結び付けない。
- `facing` を45度単位に丸め、列順に対応する64×64pxセルを描画する。
- 停止時は行0、移動時は行1〜4を8fpsで循環する。
- スプライトの色は `Color.WHITE` で描画し、P1/P2のチームカラーを画像へ乗算しない。
