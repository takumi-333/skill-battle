# UIシーン部品化と実行時接続方針

本書は、現在のGodot UI実装で採用している設計方針をまとめたものです。新しい画面やUIを追加・修正するときは、この方針を基準にします。

## 1. 基本方針

- 固定UIは `scenes/main.tscn` のシーンツリーに置き、Godotエディタのインスペクターから編集できる状態にする。
- 実行時に変化する値・状態・可変個数の部品だけをスクリプトで更新または生成する。
- UIの配置・サイズ・階層を、毎回スクリプトで作り直さない。
- 仕様の基準は `docs/specs/`、試作・案は `docs/ideas/` とし、実装判断を混在させない。

## 2. シーン構成

`main.tscn` は、ゲーム本体とUIを次のレイヤーに分ける。

```text
MatchPrototype
├─ World                  # 対戦フィールド・キャラクター
├─ UIRoot (CanvasLayer)   # 通常の画面UI
│  ├─ MenuBackground
│  ├─ Title / Home
│  ├─ Practice / Debug
│  ├─ Lobby / Connection / Result
│  └─ HUD
└─ ChallengeLayer         # スキル発動中の課題UI（UIRootより前面）
   ├─ ChallengeDimmer
   └─ Challenge
      └─ Content
```

- 画面単位の固定部品（ボタン、ラベル、パネル、入力欄、スキル枠）はシーンに定義する。
- スキルアイコンのクールダウンや軌跡など、状態によって変わる描画は専用スクリプトに残す。
- 課題ウィンドウは `ChallengeLayer` に置き、フィールドを薄暗くする `ChallengeDimmer` とパネルを分離する。

## 3. `@tool` とエディタ編集

- `@tool` は、既存シーンノードを取得してプレビュー用の見た目を整えるために使う。
- `@tool` 実行中にゲーム状態を開始したり、シーンツリーに不要なノードを増やしたりしない。
- エディタで生成したノードを保存する場合は、ノードの `owner` を編集シーンのルートへ設定する。
- 実行時専用の初期化は `if not Engine.is_editor_hint()` で分離する。

## 4. 表示・入力・描画順

- 背景テクスチャはUI部品より背面（負の `z_index`）に置き、`mouse_filter = IGNORE` にする。
- 操作部品は背景より前面に置き、`mouse_filter = STOP` を基本とする。
- 親 `Control` が非表示だと子を表示しても描画されないため、画面切り替えでは親と子の両方を状態更新する。
- 課題ウィンドウはパネルをディマーより前面に置き、パネル自身は入力を受け付ける。
- ボタン素材を `TextureRect` として重ねる場合、素材は必ずボタンの背面に置く。ボタン本体を不透明な既定StyleBoxのまま重ねない。

## 5. シグナル接続

- ボタンの接続は、同じCallableが既に接続されていない場合だけ行う。
- `@tool` のエディタ実行では接続防止用メタデータを使ってよいが、Godotがメタデータをシーン保存する点に注意する。
- 実行時起動では、エディタ保存由来の接続メタデータを除去してからUI接続処理を行う。
- 接続処理を画面初期化関数に置く場合、再初期化されても二重接続にならないようにする。
- シーンファイルへ実行時接続を手作業で記録しない。接続の正はスクリプト側に置く。

## 6. 画面遷移

画面遷移関数は、次の順序を守る。

1. `screen` / `phase` などの状態を更新する。
2. `hide_menu_panels()` で不要な画面を隠す。
3. 遷移先の親パネルを表示する。
4. 背景、HUD、課題パネル、入力フォーカスを遷移先に合わせて更新する。

ホーム、練習、デバッグ、オンライン接続、ロビー、リザルトの各画面は、遷移先のボタンが常にシーンツリー上に存在することを前提とする。

## 7. スキル発動課題UI

- 課題ウィンドウの固定レイアウトはシーンで編集する。
- `Content`、タイトル、問題文、入力欄、進捗表示、残り時間バーを非表示のままシーン保存しない。
- 実行時はキャラクターごとの仕様に応じてパネル位置・サイズを調整し、タイピング／算術／なぞりの入力部だけを切り替える。
- 課題開始時にディマーとパネルを表示し、終了時・中断時・試合リセット時に両方を非表示に戻す。
- 課題ウィンドウは画面中央より少し下を基本位置とし、対戦フィールドと相手の状態が見える領域を残す。

## 8. 変更時の確認項目

- シーンツリーに固定部品が存在し、インスペクターで位置・サイズ・文言を変更できる。
- 保存してGodotを再起動しても、ボタンの画面遷移が動作する。
- ホーム、練習、デバッグ、オンライン、ロビー、リザルトの主要遷移を確認する。
- スキル発動時に課題パネルの中身・入力欄・残り時間バーが表示される。
- ボタンの文字が見え、背景素材が入力を遮らない。
- `godot --headless --path . --quit-after 3` とエディタ起動でエラーがない。
